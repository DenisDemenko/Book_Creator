# Технічна специфікація: модуль `/diagn`
### Цифрова майстерня письменника та експерта — AI-діагностика
**Версія:** 1.0
**Дата:** 31.08.2026
**Статус:** Draft

---

## 1. Мета модуля

Команда `/diagn` дозволяє користувачу запустити AI-діагностику власного тексту або творчого профілю і отримати результат у вигляді **артефакту** — структурованого, візуально оформленого звіту, який можна переглядати в інтерфейсі, зберігати в портфоліо та експортувати (PDF/DOCX).

Діагностика будується на трьох підмодулях, що узгоджені з наявними компонентами платформи:

| Підмодуль | Що аналізує | Джерело методології |
|---|---|---|
| `style` | Авторський стиль: синтаксис, лексика, ритм, діалоги | author-style-dna |
| `structure` | Сюжет, драматургія, архетипи конфліктів | writer-mastery (36 ситуацій Польті), hero-journey |
| `competency` | Компетенції автора за картою навичок | Внутрішня компетентнісна модель платформи |

---

## 2. Синтаксис команди

```
/diagn [текст або посилання на документ] [--module=style|structure|competency|all] [--format=card|pdf|docx]
```

**Приклади:**
```
/diagn --module=style
/diagn "Уривок роману..." --module=all --format=pdf
/diagn doc:manuscript_ch3 --module=structure
```

Якщо `--module` не вказано → за замовчуванням `all`.
Якщо `--format` не вказано → за замовчуванням `card` (інтерактивний артефакт в UI, без файлу).

---

## 3. Архітектура запиту

```
[Frontend]
   │  POST /api/v1/diagn
   ▼
[Command Parser] — розпізнає /diagn, витягує аргументи, валідує вхідні дані
   │
   ▼
[Diagnostic Orchestrator] — визначає, які підмодулі запускати (1–3 паралельно)
   │
   ├──► [Style Analyzer]      → LLM-виклик #1 (system prompt: author-style-dna логіка)
   ├──► [Structure Analyzer]  → LLM-виклик #2 (system prompt: writer-mastery/hero-journey логіка)
   └──► [Competency Analyzer] → LLM-виклик #3 (system prompt: компетентнісна карта)
   │
   ▼
[Response Aggregator] — збирає JSON-результати трьох модулів в один об'єкт
   │
   ▼
[Artifact Renderer]
   ├──► format=card → React-компонент (рендер в чаті/дашборді)
   └──► format=pdf/docx → генерація файлу (ReportLab / python-docx) → посилання на завантаження
   │
   ▼
[Storage] — збереження звіту в БД, прив'язка до user_id + timestamp + document_id
```

## 4. API Endpoint

### `POST /api/v1/diagn`

**Request:**
```json
{
  "user_id": "string",
  "input": {
    "type": "raw_text | document_ref",
    "content": "string або document_id"
  },
  "modules": ["style", "structure", "competency"],
  "format": "card | pdf | docx",
  "locale": "uk"
}
```

**Response (200 OK, format=card):**
```json
{
  "diagn_id": "uuid",
  "created_at": "ISO8601",
  "modules": {
    "style": {
      "summary": "string (2-3 речення)",
      "metrics": {
        "sentence_rhythm": { "score": 0-100, "label": "string" },
        "lexical_diversity": { "score": 0-100, "label": "string" },
        "dialogue_ratio": { "score": 0-100, "label": "string" }
      },
      "highlights": [
        { "excerpt": "string", "note": "string" }
      ],
      "recommendations": ["string", "string"]
    },
    "structure": {
      "summary": "string",
      "detected_archetype": "string (напр. 'Полтті: Переслідування')",
      "arc_position": "string (напр. 'Заклик до пригоди')",
      "deviations": [
        { "type": "string", "description": "string", "severity": "low|medium|high" }
      ],
      "recommendations": ["string"]
    },
    "competency": {
      "summary": "string",
      "radar": [
        { "skill": "string", "score": 0-100 }
      ],
      "gaps": ["string"],
      "next_exercises": ["string"]
    }
  },
  "artifact_url": "null (для card) | https://.../report.pdf"
}
```

**Помилки:**
| Код | Причина |
|---|---|
| 400 | Порожній вхід / текст менше мінімального обсягу (рекоменд. ≥300 слів для style/structure) |
| 413 | Перевищено ліміт довжини тексту |
| 422 | Невідомий модуль у `modules` |
| 429 | Перевищено ліміт запитів (rate limit на LLM-виклики) |
| 500 | Помилка LLM-провайдера / таймаут |

## 5. Системні промпти (принцип побудови)

Кожен підмодуль використовує окремий system prompt, що **примусово вимагає JSON-відповідь без преамбули**, за прикладом уже реалізованого підходу в проєкті (structured outputs). Ключові вимоги до промпту:

- Явна інструкція: "Відповідай ЛИШЕ у форматі JSON, без markdown-обгортки, без вступного тексту."
- Фіксована схема полів (див. розділ 4) — щоб фронтенд міг детермінованого рендерити картки.
- Обмеження на довжину `summary` (2–3 речення) — картка має лишатись компактною.
- Локалізація: промпт явно вказує мову відповіді (`locale`).

## 6. Артефакт: візуальне представлення (`format=card`)

React-компонент `DiagnosticReportCard`:

- **Верхній блок** — загальна оцінка/summary, дата, назва документа.
- **Вкладки за модулями** (Стиль / Структура / Компетенції) — перемикання без перезавантаження.
- **Style tab** — метрики у вигляді progress-барів + виділені цитати з поясненнями.
- **Structure tab** — бейдж архетипу + позиція на кривій мономіфу (якщо застосовний hero-journey) + список відхилень з кольоровим кодуванням severity.
- **Competency tab** — радар-діаграма (recharts) + список прогалин і рекомендованих вправ.
- **Кнопка "Експортувати в PDF/DOCX"** — викликає окремий endpoint `POST /api/v1/diagn/{diagn_id}/export?format=pdf`.

## 7. Збереження та історія

- Таблиця `diagnostics`: `id, user_id, document_id, modules, result_json, created_at`.
- Історія доступна через `GET /api/v1/diagn/history?user_id=...&document_id=...` — для трекінгу прогресу автора в часі (наприклад, порівняння competency-радару за кілька місяців).
- Рекомендований TTL для кешу «сирого» LLM-результату — 24 год (щоб повторний запит на той самий текст не витрачав квоту).

---

## 8. Продуктивність і ліміти

- Паралельні LLM-виклики для трьох модулів (не послідовно) — цільовий час відповіді ≤ 15 с для `format=card`.
- Мінімальний обсяг тексту для `style`/`structure`: 300 слів (нижче — попередження про низьку достовірність аналізу).
- Rate limit: рекомендовано 10 діагностик/годину на користувача (налаштовується).

## 9. Відкриті питання для наступної ітерації

1. Чи потрібна версія `/diagn` для порівняння двох текстів (A/B аналіз стилю)?
2. Чи інтегрувати результати `competency` напряму в компетентнісну карту користувача (авто-оновлення профілю)?
3. Формат збереження звітів у портфоліо — окремий розділ чи прив'язка до конкретного документа?
