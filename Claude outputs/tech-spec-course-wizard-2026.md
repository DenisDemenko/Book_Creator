# ТЗ: майстер створення курсів (гілка «Навчальний курс»)

**Статус:** чернетка на погодження. Код не писався.
**Дата:** 05.09.2026
**Основа:** живий курс «Fusion для мебелярів» (`fusionlab.in.ua/catalog/furniture-makers`)

---

## 1. Що вже є насправді

Перш ніж пропонувати, я подивився обидва боки. Три знахідки міняють постановку
задачі, тому вони йдуть першими.

### 1.1. Курс у каталозі: структура, яку видно

З даних сторінки курсу мебелярів:

```
product {
  title, subtitle, summary, description,
  priceMinor, priceLabel, currency, coverUrl,
  highlights: string[],            // «5 модулів · 25 занять», три вигоди
  seller { displayName, slug }, category { slug, name },
  curriculum: {
    format: null,
    modules: [{
      title,                        // «МОДУЛЬ 1. Побудова скетчів (2D основа виробу)»
      lessons: [{
        title,                      // «1. Інтерфейс Fusion 360 та структура проєкту»
        goal?,                      // «навчитися точно будувати...» — є не в усіх
        topics: string[],           // один-два рядки змісту
        embedUrl?                   // https://www.youtube.com/embed/...
      }]
    }]
  }
}
```

5 модулів × 5 уроків = 25 занять, у кожного уроку свій YouTube-embed.

**Уточнення до постановки.** Ви написали «відео до кожного модуля». Насправді в
цьому курсі відео вже **до кожного уроку** — і це правильніше. Пропоную лишити
відео на рівні уроку, а на рівні модуля додати **необов'язкове** оглядове відео
(вступ до модуля), а не дублювати уроки.

### 1.2. Курс у Студії: урок — це вказівник, а не контейнер

`src/types.ts`, коментар до `CourseLesson` каже прямо:

> «Урок у структурі курсу — не новий контейнер контенту, а лише впорядковане
> посилання на вже наявні `CourseTag`… Курс лишається способом ПОДАТИ вже
> позначений матеріал послідовно, а не окремою копією контенту.»

Тобто сьогодні:

```
CourseLesson  { id, title, titleEn?, tagIds[], createdAt }     // і все
CourseModule  { id, title, titleEn?, lessons[], createdAt }
CourseMaterial{ kind: 'youtube'|'photo'|'homework'|'model_3d', tagId?, ... }
CourseConfig  { enabled, title, description?, tags[], materials[], modules? }
```

У уроку **немає** ні опису, ні мети, ні завдання, ні власних матеріалів —
матеріали чіпляються до **тегів рукопису**, а не до уроків. Модуль має лише
назву.

І головне: `CourseConfig` живе **всередині книги** (`Book.courseConfig`). Курс у
Студії — це похідне від рукопису.

**А курс мебелярів жодного рукопису не має.** Fusion 360, скетчі, ЧПУ — там
немає книги, з якої це «походить».

### 1.3. Міст у маркетплейс возить лише цифри

`server/marketplaceBridge.ts`, `publishCourseToMarketplace` шле:

```
externalId, title, subtitle, summary, description, priceMinor,
coverUrl, highlights, sellerSlug, moduleCount, lessonCount
```

**`curriculum` там немає.** Тобто структура, яку видно на сторінці курсу
мебелярів, через цей міст не проходила — її заводили на боці маркетплейсу
окремо. Хоч що згенерує майстер, у каталог воно сьогодні не доїде.

### 1.4. Медіатека — тільки зображення

`MediaLibraryView` працює з `book.illustrations: BookIllustration[]`. Поля
`kind` немає взагалі, відео немає, файли лежать як data URL під квотою сховища.

### 1.5. Ролей «експерт» і «викладач» не існує

`UserRole = admin | writer | designer | translator | publisher | reader | guest`.

## 2. Три рішення, які треба ухвалити ДО коду

Це не деталі реалізації — від відповідей залежить обсяг робіт і те, чи не
доведеться переробляти за місяць.

### Рішення 1. Курс стає самостійною сутністю (рекомендую «так»)

Сьогодні курс — вкладка всередині книги. Курс мебелярів показує, що курси
бувають без книги взагалі.

| | Курс усередині книги (як зараз) | Курс як окрема сутність |
|---|---|---|
| Курс без рукопису | неможливий | природний |
| Міграція наявних курсів | не потрібна | потрібна (вони лишаються як є) |
| Обсяг | малий | середній: нова таблиця, свої маршрути |
| Автор — не письменник | не вписується | вписується |

**Рекомендую:** нова сутність `Course` зі своїм сховищем. Наявний
`Book.courseConfig` лишається робочим і не чіпається — той сценарій («зробити
курс із моєї книги») теж валідний, просто він не єдиний.

### Рішення 2. Урок стає контейнером контенту (без цього решта неможлива)

Ваші вимоги — опис до кожного уроку, завдання до кожного уроку, фото й відео —
означають, що урок мусить мати власні поля. Вказівником на теги рукопису він
лишитися не може: у курсу мебелярів рукопису немає, а отже й тегів.

**Рекомендую:** у новій сутності урок — повноцінний контейнер. Стара модель
(урок-вказівник) лишається для курсів, зроблених із книги.

### Рішення 3. Відео — це посилання, а не файл

Медіатека тримає файли як data URL під квотою. Одне відео на 200 МБ з'їсть
квоту цілком.

**Рекомендую:** розділ «Відео» в медіатеці зберігає **посилання** (YouTube і
Vimeo) з назвою, описом, обкладинкою й прив'язкою до модуля/уроку. Завантаження
відеофайлів — окрема задача про об'єктне сховище, і в це ТЗ вона не входить.

## 3. Модель даних

Курсивом — те, чого сьогодні немає.

```
Course
  id, ownerId, status: 'draft' | 'ready' | 'published'
  title, subtitle, summary, description
  audience: string[]              // «Дизайнери меблів», «Конструктори»
  outcomes: string[]              // «Результати навчання» — уже є в каталозі
  highlights: string[]            // три вигоди на картці
  coverUrl
  category, priceMinor, currency
  skills: CourseSkill[]           // ← новий блок, див. 3.1
  modules: CourseModuleV2[]
  createdAt, updatedAt, publishedAt

CourseModuleV2
  id, title, summary                    // ← опис модуля (зараз лише назва)
  coverPhotoId                          // ← фото модуля (з медіатеки)
  introVideoId                          // ← необов'язкове оглядове відео
  lessons: CourseLessonV2[]
  finalAssignment: Assignment           // ← завдання наприкінці модуля
  skillIds: string[]                    // ← які навички розвиває цей модуль

CourseLessonV2
  id, title
  goal                                  // мета одним реченням (є в каталозі)
  description                           // ← окремий опис уроку
  topics: string[]                      // зміст, як у каталозі
  videoId                               // відео уроку (посилання)
  photoIds: string[]                    // ← фото уроку
  assignment: Assignment                // ← завдання до уроку
  durationMin?

Assignment                              // ← нове
  id, title, brief                      // що зробити
  steps: string[]                       // покроково
  deliverable                           // що студент здає: файл, фото, текст
  acceptanceCriteria: string[]          // «зроблено правильно» — критерії
  estimateMin?

CourseSkill                             // ← нове, див. 3.1
  id, name, level: 'base'|'confident'|'pro'
  whyItMatters                          // навіщо ця навичка в ремеслі
  howToDevelop: string[]                // як її розвивати далі
  practiceIdeas: string[]               // вправи поза курсом
```

### 3.1. Блоки про навички — і чому не переписувати наявне

У Студії вже є система навичок письменника (`MasteryView`, колесо навичок,
тренажери). Спокуса — перевикористати її. **Не варто:** там навички
письменницькі й прив'язані до рукопису, а тут вони предметні (робота зі
скетчами, параметризація, підготовка до ЧПУ) і в кожного курсу свої.

Пропоную `CourseSkill` як власну легку сутність курсу, з тими самими двома
питаннями, що й у вашій вимозі: **що це за навичка** і **як її розвивати**.
Блок показується двічі — у картці курсу (загальний перелік) і в модулі (які
саме навички він розвиває).

## 4. Медіатека: розділи «Фото» і «Відео»

```
MediaAsset
  id, kind: 'photo' | 'video'
  title, description?
  // kind === 'photo'
  url (data URL або файл), fileSize, width, height
  // kind === 'video'
  provider: 'youtube' | 'vimeo', embedUrl, thumbnailUrl?, durationSec?
  // спільне
  courseId?, moduleId?, lessonId?     // структурування за курсом
  tags: string[]
  createdAt
```

- Наявні `BookIllustration` мігрують у `kind: 'photo'` без втрат.
- Інтерфейс медіатеки отримує дві вкладки — **Фото** і **Відео** — і фільтр за
  курсом / модулем / уроком, щоб «завантажити структуровано» означало не «звалити
  в купу», а «покласти туди, де воно потрібне».
- З майстра й з екрана «Створити курс» медіатека відкривається як **вибір**
  («взяти фото модуля з медіатеки»), а не лише як сховище.

## 5. Майстер: гілка «Навчальний курс»

Замість припущення з п'яти кроків, яке зараз показує заглушка, пропоную шість.
Кожен крок — один екран, модель пропонує чернетку, автор править.

| # | Крок | Що питаємо | Що пропонує модель |
|---|---|---|---|
| 1 | **Тема й аудиторія** | ремесло, для кого, рівень входу | назву, підзаголовок, 2–4 портрети аудиторії |
| 2 | **Результати навчання** | що людина вмітиме наприкінці | 3–6 результатів + три вигоди на картку |
| 3 | **Навички** | які навички розвиває курс | перелік `CourseSkill` з «навіщо» і «як розвивати» |
| 4 | **Модулі** | великі блоки шляху | 4–6 модулів: назва, опис, які навички закриває |
| 5 | **Уроки** | наповнення модулів | по 3–6 уроків: назва, мета, опис, зміст |
| 6 | **Практика** | що студент робить руками | завдання до кожного уроку + підсумкове до модуля |

Медіа в майстер **не** входять навмисно: підбирати фото й відео до 25 уроків у
режимі «за 5 хвилин» неможливо, і спроба це зробити перетворить швидкий майстер
на довгу форму. Майстер дає **каркас із текстом**, медіа чіпляються далі, на
екрані «Створити курс», де для цього є місце й медіатека під рукою.

Наприкінці майстер зберігає `Course` зі статусом `draft` і веде автора на екран
редагування.

## 6. Роль і екран «Створити курс»

### 6.1. Ролі

Додаються дві:

```
'expert'   // Експерт: носій ремесла, автор змісту курсу
'teacher'  // Викладач: веде курс, править методику, перевіряє завдання
```

У матриці прав (`RolePermission`) обом відкривається новий доступ
`canAuthorCourses`. Адміністратор отримує його автоматично, як і решту.

### 6.2. Пункт меню

«Створити курс» з'являється в меню Fusion Lab Studio **лише** для ролей
`expert`, `teacher`, `admin`. Решта ролей пункту не бачать — не «бачать
вимкненим», а не бачать: інакше кожен письменник питатиме, чому йому не можна.

### 6.3. Що на екрані

Три панелі:

1. **Дерево курсу** — модулі й уроки, перетягування, додавання, видалення.
2. **Редактор вибраного** — поля модуля або уроку: опис, мета, зміст, відео,
   фото, завдання, навички. Тут же кнопка «взяти з медіатеки».
3. **Готовність до публікації** — чесний перелік того, чого бракує: «У модуля 3
   немає фото», «В уроці 2.4 немає завдання», «Не заповнені критерії приймання
   в 5 завданнях». Поки перелік не порожній, курс лишається `draft`.

## 7. Що доведеться змінити в маркетплейсі

Це окремий репозиторій (`Fusion-Lab-Marketplaes`), тому виношу окремо.

Міст сьогодні возить `moduleCount` і `lessonCount`. Щоб курс із майстра
з'явився в каталозі так, як курс мебелярів, потрібно:

1. Розширити тіло `POST /bridge/courses` повним `curriculum` (модулі, уроки,
   мета, зміст, відео) плюс новими полями: фото модуля, завдання, навички.
2. Розширити схему на боці маркетплейсу (Prisma) під ці поля.
3. Оновити сторінку курсу, щоб вона показувала фото модулів, завдання й блок
   навичок — зараз вона їх просто не знає.

**Без цього кроку** майстер працюватиме, курс жити в Студії буде, а в каталозі
з нього буде видно те саме, що й зараз: назву, ціну й дві цифри.

## 8. Порядок робіт

| Фаза | Зміст | Результат |
|---|---|---|
| **0** | Ролі `expert`/`teacher`, право `canAuthorCourses`, пункт меню | роль є, екран порожній |
| **1** | Сутність `Course` + сховище + маршрути | курс існує без книги |
| **2** | Медіатека: `kind`, вкладки «Фото»/«Відео», прив'язка до курсу | медіа структуровані |
| **3** | Екран «Створити курс»: дерево, редактор, готовність | курс можна зробити руками |
| **4** | Майстер: 6 кроків гілки `course`, статус `ready` | курс за 5 хвилин |
| **5** | Міст + маркетплейс: повний `curriculum` у каталозі | курс видно покупцеві |

Фази 0–3 дають робочий продукт без майстра. Фаза 4 — швидкість. Фаза 5 — гроші.
Порядок навмисно такий: майстер, який генерує в нікуди, перевіряти нічим.

## 9. Питання, на які потрібна ваша відповідь

1. **Курс як окрема сутність** — погоджуєте (Рішення 1)? Це найбільша розвилка.
2. **Відео лише посиланням** (Рішення 3)? Чи потрібне завантаження відеофайлів
   уже зараз — тоді це окрема задача про сховище.
3. **Дві ролі чи одна?** Я розділив `expert` (носій ремесла) і `teacher` (веде
   й перевіряє). Якщо різниці в правах не буде — краще одна роль.
4. **Ціна й продаж** — курс із майстра одразу отримує ціну й продавця, чи це
   окремий крок публікації?
5. **Перевірка завдань.** Модель `Assignment` описує, що студент здає. Чи потрібен
   у цій ітерації сам приймальник (студент завантажує роботу, викладач
   перевіряє), чи поки досить опису завдання в курсі?
6. **Фаза 5 (маркетплейс)** — беремо в цю роботу чи окремою задачею?
