# Локальний сервер приватного сховища

Docker-сервер, який автор запускає **на власному комп'ютері**, щоб книги, курси й інструкції з галочкою
«Приватне збереження на локальному сервері» лежали лише в нього. У хмарі (Studio, Railway) вмісту таких
матеріалів немає: Studio знає лише, що сервер існує, і видає браузеру автора короткий підписаний доступ.

Хмара лишається типовим варіантом. Приватне збереження вмикається окремо на кожному матеріалі, а сам сервер
підключається **лише після підтвердження поштою й кодом**.

```
браузер автора ──(токен від Studio)──►  127.0.0.1:8787  (Docker, цей комп'ютер)   вміст: тільки тут
      │                                          ▲
      └── POST /api/private-store/:id/token      │ пульс кожні 60 с, підписаний ключем сервера (вихідний HTTPS)
                       ▼                         │
                    Studio (хмара)  ◄────────────┘   знає: назву, «в мережі», кількість записів, обсяг
```

Вхідних портів і тунелів немає: сервер сам ходить до Studio. Порт публікується лише на `127.0.0.1`, тож з інших
пристроїв мережі сервер недоступний.

## Швидкий старт

1. Адмін Studio відкриває адмінпанель → вкладка **«Локальні сервери»** → створює запис (назва, адреса,
   дозволені сторінки Studio, кому призначено).
2. На пошту адміністратора приходить **код підтвердження** (8 символів, 15 хв, 5 спроб). Його введення дає
   **одноразовий код підключення** `PS-XXXX-XXXX-XXXX` (15 хв) і готову команду розгортання.
3. На комп'ютері автора, де встановлено Docker:

   Windows (PowerShell):

   ```powershell
   cd services\private-store
   .\scripts\start.ps1
   ```

   Linux / macOS:

   ```bash
   cd services/private-store && ./scripts/start.sh
   ```

   Перший запуск створює `.env` — впишіть `STUDIO_URL` і `PAIRING_CODE`, запустіть скрипт ще раз. Він же створить
   головний ключ (`secrets/private_store_master_key`), збере образ і запустить контейнер.
4. Перевірте: `http://127.0.0.1:8787/v1/health` → `"paired": true, "status": "active"`. У вкладці адмінпанелі
   сервер покаже «в мережі». Код підключення після цього можна прибрати з `.env`.

## Що захищено і від кого

| Загроза | Захист |
| --- | --- |
| Хтось у мережі дістається сервера | Порт лише на `127.0.0.1`; перевірка `Host` (421); контейнер без прав адміністратора, `read_only`, `cap_drop: ALL`, `no-new-privileges`, ліміти пам'яті й процесів |
| Чужа веб-сторінка звертається до сервера з браузера автора | Перелік дозволених `Origin` від Studio (403, CORS-заголовків немає); лише JSON; токен у заголовку, не в cookie |
| Підроблений або вкрадений доступ | Токен `v1.<payload>.<підпис>` Ed25519, живе ≤ 15 хв, привʼязаний до сервера (`aud`) і користувача (`sub`) та видів матеріалів; відкликання з адмінпанелі доходить за пульсом |
| Підбір токенів | Ліміт запитів з IP і окремо ліміт хибних токенів (429) |
| Чужий користувач Studio читає матеріали сусіда | Кожен запис належить власнику з токена; чужий id — «зайнятий», а не перезапис |
| Викрадення диска або тома | Усе зашифровано AES-256-GCM (вміст, мета, зображення, стан), ключ шифрування — похідний від головного ключа, що лежить **окремим файлом** (Docker secret); AAD привʼязує шифротекст до місця запису |
| Підміна записів у файлі бази | AAD (`doc:<id>:payload`, `asset:<id>`…): переставлений шифротекст не розшифровується |
| Збій налаштувань | Немає ключа, слабкий ключ або хибний `STUDIO_URL` — сервер **не стартує** (fail closed) |
| Підслухати зв'язок зі Studio | `STUDIO_URL` лише `https` (http дозволено тільки для `localhost`/`host.docker.internal` під час перевірки) |

Журнал дій (`audit`) містить час, користувача, дію й ідентифікатор запису, **без вмісту**.

### Чого сервер не захищає

* **Комп'ютер автора.** Якщо в нього вкрали розблокований комп'ютер, разом із вкраденим файлом ключа й томом дані
  відкриються. Тримайте ключ окремо від тому (менеджер паролів, зовнішній носій).
* **Браузер автора.** Книга зберігає локальну копію в IndexedDB цього браузера (так працює редактор), а курси й
  інструкції живуть у памʼяті відкритої вкладки до збереження. Це теж «лише локально», але не на сервері.
* **Охоронець у браузері — страховка, а не ізоляція.** Поки приватний матеріал відкритий, браузер блокує запити зі
  вмістом до Studio (ШІ, PDF, медіатека, публікація, співавтори). Це перелік маршрутів: нові маршрути, додані
  згодом, слід вносити в `BLOCKED_PREFIXES` у `src/utils/privateStore.ts`.

## Що для приватних матеріалів недоступне (суворий режим)

Рішення власника: вміст лишається лише локально, тому недоступне все, що вимагає хмари:

* **ШІ** (майстри, поглиблення кроків, розпізнавання), **верстка PDF через Studio**, **медіатека**, **публікація**
  (курс у вітрину, експорт), **співавтори**, **спільний перегляд**;
* **GrabFusion**: чернетки з телефона створюються в хмарі (розпізнавання знімків потребує ШІ). Телефон лише показує
  стан сервера (`GET /api/external/v1/photo-drafts/private-stores`: назва, «в мережі», види; без адреси);
* швидкий друк інструкції в браузері й експорт JSON працюють.

Якщо сервер вимкнений, матеріали на ньому **недоступні**, і інтерфейс пише про це прямо (запустіть `docker compose up -d`).
Хмарної копії немає, тож без сервера їх не відкрити.

## Резервні копії й відновлення

Дані лежать у томі Docker `nova-private-store_private_store_data` (SQLite, усе зашифровано). **Без головного ключа
вони не відновлюються — ні вами, ні Studio.** Зробіть копію ключа одразу й окремо від тому.

Копія тому (сервер краще зупинити):

```bash
docker compose stop
docker run --rm -v nova-private-store_private_store_data:/data -v "$PWD":/backup alpine tar czf /backup/private-store-backup.tgz -C /data .
docker compose start
```

Відновлення в порожній том:

```bash
docker compose stop
docker run --rm -v nova-private-store_private_store_data:/data -v "$PWD":/backup alpine sh -c "rm -rf /data/* && tar xzf /backup/private-store-backup.tgz -C /data && chown -R 10001:10001 /data"
docker compose start
```

Перенесення на інший комп'ютер: том + файл ключа; потім адміністратор у вкладці «Локальні сервери» запускає
**перепідключення** (знову поштою й кодом) — записи й дані лишаються на місці.

## Видалення

* `docker compose down` — зупиняє й прибирає контейнер, **дані в томі лишаються**.
* `docker compose down -v` — **знищує том, тобто всі приватні матеріали**. Хмарної копії немає.
* Файл `secrets/private_store_master_key` у Windows захищений правами лише на читання й запис (без видалення): щоб прибрати його разом із текою, спершу дайте собі повні права (`icacls <файл> /grant "%USERNAME%:(F)"`). Видаляйте ключ лише тоді, коли тома з даними вже немає або копія ключа збережена окремо.

## Обмеження й відомі нюанси

* **Chrome і доступ до локальної мережі.** Коли сторінка Studio відкрита з публічного `https`, а сервер — на
  `http://127.0.0.1`, нові версії Chrome можуть один раз спитати дозвіл на «доступ до пристроїв у локальній мережі».
  Дозвольте його для сайту Studio. Це поведінка браузера, не помилка сервера (сервер відповідає на запит
  попередньої перевірки `Access-Control-Allow-Private-Network`).
* **Адреса в локальній мережі** (`http://192.168…`) із публічної `https`-сторінки заблокована браузером як змішаний
  вміст. Для неї потрібен `https` на самому сервері або обслуговування Studio з тієї ж мережі.
* Ліміти: документ до 64 МБ (`PRIVATE_STORE_MAX_BODY_MB`), зображення до 25 МБ, `meta` до 8 КБ.
* Один запис — один власник; ділитися приватним матеріалом із іншим користувачем не можна.

## Налаштування (змінні середовища)

| Змінна | Типово | Призначення |
| --- | --- | --- |
| `STUDIO_URL` | — (обовʼязкова) | Адреса Studio, `https` |
| `PAIRING_CODE` | порожньо | Одноразовий код підключення з адмінпанелі |
| `PRIVATE_STORE_PORT` | `8787` | Порт (публікується лише на `127.0.0.1`) |
| `PRIVATE_STORE_PUBLIC_URL` | `http://127.0.0.1:8787` | Адреса, за якою браузер звертається до сервера |
| `PRIVATE_STORE_NAME` | `Локальний сервер` | Назва в адмінпанелі |
| `PRIVATE_STORE_ALLOWED_HOSTS` | — | Додаткові дозволені `Host` |
| `PRIVATE_STORE_ALLOWED_ORIGINS` | — | Додаткові дозволені `Origin` (понад ті, що дає Studio) |
| `PRIVATE_STORE_HEARTBEAT_SEC` | `60` | Частота пульсу до Studio |
| `PRIVATE_STORE_RATE_LIMIT` | `1200` | Запитів на хвилину з одного IP |
| `PRIVATE_STORE_MAX_BODY_MB` | `64` | Найбільший запис |

## Перевірка

Із кореня репозиторію (без Docker, сервер піднімається в тому ж процесі):

```bash
npm run test:private-store
```

Покривають: шифрування й привʼязку до місця, токени (підпис, строк, аудиторія, відкликання), власника й ревізії, відсутність
відкритого тексту у файлі бази, підключення лише за поштою й кодом (ліміт спроб, одноразовість), CORS/Host/Origin,
пульс, перепідключення, стан для GrabFusion і блокування охоронцем у браузері.
