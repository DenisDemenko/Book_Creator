## 597. GrabFusion: герой з фото для наявної книги → ✅ Розгорнуто

**Сесія Claude: 22.11.2026 #05**

**Постановка.** Камера або медіатека → опис прототипу → перевірка автором → «Книга і текст → Герої» та медіатека цієї книги.

**Зміни.** Використано наявне розпізнавання GrabFusion та облік витрат. Опис видимих деталей показано окремо від вигаданого характеру. Затвердження створює героя в книзі автора, а завантажене фото записує до її медіатеки. Уже наявне фото повторно використовується. Зі Студії передається ID відкритої книги, з GrabFusion можна відкрити картку героя. Імена й обидва тексти редагуються до збереження.

**Перевірка.** JavaScript GrabFusion розбирається. Модель клієнтського потоку пройшла підстановку книги, розпізнавання, редагування та ручне затвердження. До A5 додано регресійні HTTP-тести доступу, збереження, повтору та медіатеки.

**Не зроблено і чому.** Виконання TypeScript, Python, HTTP-тестів та живий прохід через iPhone потребують доступного середовища. Зміна публікується лише в окремій дозволеній гілці.

## 598. Однаковий вибір «хмара / локальний сервер» для книг, курсів та інструкцій у GrabFusion і Студії → ✅ Розгорнуто

**Сесія Claude: 22.11.2026 #03**

**Постановка (власник).** Два сховища — хмара й локальний сервер у Docker; для матеріалів суворої конфіденційності автор обирає, куди йдуть дані. «Перевір, чи можу я книгу зберегти лише локально… Grab Fusion не пропонував альтернатив для книг». Потім: «зроби обидва шляхи однаковими для курсів, інструкцій та книг в Grab Fusion та студії книг».

**Що було.** У Студії при створенні галочка «Приватне збереження» вже є для всіх трьох видів (адмінка → «Локальні сервери» визначає, які види приймає сервер і кому він призначений). Але: наявний матеріал не можна було перенести між хмарою й сервером; у GrabFusion приватного шляху не було для курсу з фото, а для «Створити книгу» з фото він пропонувався, хоча локальний сервер таку чернетку відхиляв («Невідомий вид чернетки»); рукопис до наявної книги — лише в хмарі; до приватних знімків не можна було дописати нотатку.

**Реалізація.**
- **Локальний сервер** (`services/private-store/src/inbox.mjs`): книга з фото приймається як `manuscript` з `photoBook`; `isPhotoDraft` для курсу з фото й книги з фото — автоматично розпізнає лише Ollama (якщо налаштовано), Tesseract на фото не запускається; без Ollama основа тексту — нотатки до кадрів.
- **GrabFusion** (`private.js`, `app.js`, `i18n.js`): «Де обробити» — для інструкції, курсу (фото й документ), книги з фото й книги зі сторінок. Поле «Нотатка до кадру» на екрані приватної чернетки (іде всередині зашифрованого конверта). Рукопис «до існуючої книги» приватно — книга обирається на компʼютері.
- **Студія, перевірка знімків** (`PrivateScanReview.tsx`, `shared/localScanStructure.ts` → `structurePhotos`, `photoPageText`): для фото кадр = урок курсу / фрагмент книги, текст — нотатка + опис Ollama; «Куди додати: нова приватна книга / до наявної приватної книги» (`appendToPrivateBook` у `localScanBuild.ts`).
- **Студія, перенесення** (`StorageMoveBar.tsx`, однаковий для трьох видів): над редактором книги, курсу й інструкції — «Перенести на локальний сервер» / «Перенести в хмару». Порядок: запис у нове місце → перевірка → видалення старої копії. Книга — `App.tsx` (`moveBookToPrivate/ToCloud`, `forgetServerRevision`); курс — `CourseStudioLegacy.tsx` (опублікований чи на модерації — не переноситься); інструкція — `InstructionBuilderView.tsx` («хмарний» шлях інструкцій — чернетка в цьому браузері, так і підписано). Охоронець приватності пропускає `DELETE` (вмісту не несе) — ним прибирається хмарна копія.

**Перевірка.** `lint` (tsc) — 0. `test:private-store` 107/107 (+1: DELETE не блокується), `test:private-inbox` 70/70 (+6: книга з фото, курс з фото → Ollama, без Ollama — без розпізнавання, нотатка збережена), `test:local-scan-structure` 52/52 (+7: кадри з фото, додавання до наявної книги), `instruction-builder-view`, `instruction-draft`, `my-works`, `admin-os`, `course-document`, `photo-drafts-a5` — зелені. GrabFusion pytest — 191 пройдено, нова наскрізна `test_private_path_is_offered_for_every_kind` (Chrome) зелена; 6 падінь (`test_contract` ×2, `test_mock_sim`, `test_e2e_browser` stage3/stage5, `test_e2e_pwa`) є й на чистому `master`. Браузер (Chrome, відповіді сервера підмінено): книга «в хмару → на сервер → у хмару» — порядок запитів правильний, у приватному стані жодного запису в хмару; екран перевірки книги з фото — нотатки стали текстом, «Додати до приватної книги».

**Чого перевірка НЕ покрила.** Справжній Docker-сервер і телефон (наскрізно). Перенесення курсу й інструкції в браузері — лише типи й код, без прогону. Зображення з хмарної медіатеки в перенесеній книзі/курсі лишаються посиланнями на хмару (попередження в підтвердженні). Фото з кадрів книги з фото в саму приватну книгу не вставляються — лишаються в чернетці на сервері. Перенесення курсу дає йому новий ідентифікатор (старі посилання на курс не працюватимуть). Правила «лише приватно» для користувача в адмінці немає — не почато.
