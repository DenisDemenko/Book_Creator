# Т7.6 — Visual Bible та Style Bible

Маршрути Студії: `/creative/bible/:bookId` і `/creative/style/:bookId` (під `/studio` на production). Вхід із Workspace та вкладки «Походження» медіатеки. API — `/api/creative/bible/:bookId`.

## Дозволи й канон

Власник книги керує обома розділами. Іншим активним учасникам потрібен явний чинний grant `visual_bible` / `style_bible`, `scopeRef = bookId`: VIEW для читання, MANAGE для змін. Навіть MANAGE на всю книгу або роль адміністратора не дають учасникові окремого дозволу змінювати Bible. Доступ до файла (`media_asset` / медіатека / книга) і сутності перевіряється додатково. Немає автоматичних grants.

«Додати до візуального канону» — підтверджена окрема дія. Приймається конкретна APPROVED версія файла з approval. Для персонажа, локації, предмета потрібна відповідна сутність і вже підтверджений, не позначений needsReview зв’язок `asset_entity_links`. Версія зовнішності з цього зв’язку має бути approved. Створити / підтвердити зв’язок можна наявною панеллю «Прив’язки» медіатеки. Копія файла не створюється й додаткова квота не списується.

Запис канону незмінний: точна версія файла, походження й approval, знімок зв’язку та зовнішності, ID активної версії стилю, правила образу, головний образ, категорія, виконавець і час. Один активний головний образ на сутність / категорію; один активний запис на файл. Для нових правил / образу потрібні окреме вилучення з причиною та нове підтверджене додавання. Вилучення повертає файл у APPROVED, зберігає історію, не видаляє його.

Категорії: персонажі, локації, предмети, костюми, транспорт, архітектура, істоти, символи, палітри, обкладинки. Правила: опис, ракурс, вираз, одяг, візуальний вік, ознаки, заборонені зміни; час доби, сезон, архітектура, світло, матеріали, кольори, погода, ключові об’єкти, заборонені елементи. Сцени успадковуються з походження файла; відповідь показує лише дозволені сцени. Зображення / відео відображаються у картці; інші формати доступні через приватне посилання.

## Зберігання і аудит

Адитивні SQLite-таблиці `creative_bible_entries`, `creative_style_versions`, `creative_style_active`, `creative_bible_audit`. Канон, CAS зміна provenance у медіатеці, медіаісторія та аудит записуються однією синхронною SQLite-транзакцією без await усередині. Помилка будь-якого запису відкочує все. Звичайне редагування provenance або видалення CANON заблоковані. SQLite видалення медіа прибирає metadata / пише історію до асинхронного unlink, щоб конкурентне додавання не канонізувало вже видалюваний файл.

Core (Memory / PostgreSQL) лише читається для чинних grants, сутностей, `asset_entity_links` та зовнішності; перед commit зв’язок / зовнішність перевіряються повторно. Між Core і SQLite немає вигаданої спільної транзакції: канон зберігає перевірений знімок, подальші зміни Core не переписують його. Аудит доступний власнику, журнал канону залишається після вилучення. Production має використовувати спільний SQLite книг і медіатеки; JSON-only режим Bible повертає 503, старі операції медіатеки з JSON продовжують працювати.

## Style Bible

Поля: жанр, настрій, візуальний / емоційний тон, основна / додаткова / акцентна палітра, заборонені кольори, освітлення, контраст, композиція, кадрування, дистанція камери, безпечні зони заголовка, фотографічна / ілюстративна мова, заборонені стилі. Версії незмінні; «Взяти за основу» створює нову версію, не редагує попередню. Збереження версії й активація — різні підтверджені дії. Активація захищена CAS і журналюється. Затверджені assets та наявні записи канону не змінюються.

GET `/context` повертає schema 1, активний Style Bible та канонічні референси лише дозволених сутностей, матеріалів і сцен. Потрібні VIEW обох розділів; немає рукопису, прихованих сутностей, повних промптів чи ключів. UI показує цей JSON людині. Підключення генераторів і зміна стилю конкретної AI-задачі — окремий Т7.7. UI перечитує права кожні 5 секунд і прибирає вміст після відмови; App remount при зміні акаунта.

## Перевірка

`npm run test:creative-bible`: реальні Express, SQLite й Core, права / CAS / аудит / перезапуск / rollback. Той самий прогін із `CORE_TEST_DATABASE_URL` використовує ізольований PostgreSQL. `--browser`: справжній React + API, підтвердження канону, створення / активація стилю, структурований контекст, другий учасник / відкликання, мобільний екран 390px. Повний `npm test`, `npm run lint`, `npm run build`.

Ручне production-приймання: [docs/acceptance/T7.6.md](docs/acceptance/T7.6.md).
