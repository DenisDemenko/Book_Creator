# Формат пакета змін (pack v2) — для хмарної сесії

Цей файл — інструкція тій сесії, яка **готує** зміни в хмарі й не має доступу
до GitHub (мережева політика). Вона складає пакет; на машині власника його
застосовує `scripts/commit-pack.ps1`. Формат змінився 26.09.2026 після двох
втрат — причина й докази в журналі, записи **#264** і **#265**.

## Що везе пакет

```
pack.tgz
├── manifest.json         ← обов'язково
├── 0001-code.patch       ← зміни коду (git diff, не знімки файлів)
├── 0002-docs.patch       ← (якщо треба) без журналу — див. нижче
├── msg1.txt, msg2.txt    ← повідомлення комітів, по одному на коміт
└── journal-entry.md      ← (необов'язково) ТЕКСТ запису журналу, не файл
```

**Чого в пакеті бути не може:**

- копій `log.md`, `log/*.md`, `task.md`, `PLAN_*.md` — журнал і план пише та
  машина, що виконує пакет, і лише локально (`npm run journal:new`). Інакше
  номер запису зіштовхується з уже наявним, а локальні правки журналу
  зникають: 26.09.2026 копія журналу з пакета затерла запис #263;
- копій цілих файлів замість патчів — пакунок зі знімками відкочує все, чого
  завдання не торкалося: `package.json`, `server.ts`, `server/db.ts`,
  `src/components/EditorView.tsx`, `src/i18n/dictionaries/index.ts`
  поверталися так до стану до #259.

## manifest.json

```json
{
  "title": "Т2.3 В4 — AI-3: розпізнавання й звірка з описом",
  "baseCommit": "595adc17d06e9eb9dbb71345598b267c7408f8c7",
  "allowDirty": [],
  "commits": [
    {
      "label": "core: AI-3 розпізнає зображення й звіряє з описом",
      "patch": "0001-code.patch",
      "files": [
        "server/core/types.ts",
        "server/core/visual.ts",
        "src/components/MediaLibraryView.tsx"
      ],
      "message": "msg1.txt",
      "tests": ["test:visual-review", "test:visual-links"],
      "fill": []
    },
    {
      "label": "log: #266 — запис журналу",
      "patch": "0002-docs.patch",
      "files": ["task.md", "PLAN_VISUAL_LIBRARY.md"],
      "message": "msg2.txt"
    }
  ]
}
```

Поля:

| Поле | Обов'язкове | Що це |
|---|---|---|
| `title` | так | назва пакета, друкується на початку прогону |
| `baseCommit` | **так** | **повний** 40-символьний SHA коміта, на якому зібрано патчі |
| `allowDirty` | ні | шляхи, які скриптові дозволено побачити зміненими (не використовуй без потреби) |
| `commits[].label` | так | друкується перед кожним комітом |
| `commits[].patch` | так* | файл `git diff` усередині пакета |
| `commits[].files` | **так** | **кожен** шлях, який цей коміт пише; скрипт звіряє з ним дерево |
| `commits[].message` | так | файл із повідомленням коміта |
| `commits[].tests` | ні | `npm run`-цілі, які прогнати **перед** комітом |
| `commits[].fill` | ні | файли, де замінити `@@C1@@`, `@@C2@@` на короткі хеші попередніх комітів пакета |
| `commits[].extract` | ні* | `.tgz` — лишається для сумісності, але з архіву копіюються **лише** файли з `files` |

\* рівно одне з `patch` / `extract` на коміт. Патч бажаний: він несе зміну, а
не стан.

**Патч має бути звичайним `git diff`** (`git diff <base>..HEAD > 0001-code.patch`),
а не `git format-patch`: тоді скрипт застосовує його через `git apply --3way`
і прогоняє тести **до** коміта. Mailbox (`From …`) теж приймається, але
`git am` комітить його сам, і тести підуть після коміта.

Порядок комітів у пакеті — порядок застосування. Кожен коміт окремо:
код і журнал не змішувати (правило репозиторію).

## Що перевірить локальний скрипт (де він зупиниться)

1. `tmp/session.lock` — якщо робочу копію вже займає інший прогін або
   інтерактивна сесія, прогон не почнеться;
2. `baseCommit` — повний хеш `HEAD` мусить збігатися, інакше STOP (самої теми
   коміта замало);
3. у дереві не має бути змінених файлів, яких пакет не оголосив (файли
   журналу/плану — виняток: вони можуть бути незакомічені, скрипт про них
   попередить);
4. жоден шлях із `files` / `fill` не може бути `log.md`, `log/*.md`,
   `task.md`, `PLAN_*.md` — це STOP: журнал пише машина;
5. після кожного кроку — звірка дерева з `files`: зайвий змінений файл
   зупиняє прогон **до** коміта;
6. після всіх комітів — `npm run journal:check`.

## Чекліст перед пакуванням

- [ ] `git diff <baseCommit>..HEAD --stat` показує рівно те, що має їхати;
- [ ] у `files` перелічено **всі** шляхи кожного коміта — патч і `files`
      мусять збігатися за складом;
- [ ] журналу й плану в пакеті немає; текст запису — у `journal-entry.md`;
- [ ] `baseCommit` — це `git rev-parse HEAD` **на машині власника**, а не
      здогад: хмарний клон може відставати, і саме на цьому будувалася
      пастка 26.09.2026;
- [ ] у повідомленнях комітів — трейлер `Co-Authored-By:` і жодних посилань
      на сесію (репозиторій публічний).
