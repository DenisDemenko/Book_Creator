# Т6.2 — Access Grant (Наданий доступ) і фактичні права

Продовження `task.md` (етап 6, Т6.2) і `PLAN_COLLABORATION.md` (Т6.1).
Формат — як попередні плани: що вже є, рішення, етапи В1…Вn.

Джерела: ТЗ Graph Studio v3.0 §49 (Access Graph View: рівні VIEW / COMMENT /
EDIT / CREATE / REVIEW / APPROVE / MANAGE, області BOOK / CHAPTER / SCENE /
CHARACTER / LOCATION / STYLE_BIBLE / MEDIA_LIBRARY / TASK / DELIVERABLE;
приклад «Марія / Ілюстратор»; менеджер книги без канону), §37, §59 №36–38, 44;
ТЗ Role Onboarding §19 (роль ≠ дозвіл: учасник + проєкт + роль + область +
наданий доступ = фактичні права), №8, 11, 18, 20, 22, 24; ТЗ Creative Studio
(«заборонена сутність недоступна через UI і прямий API», рівні NONE / WORK).

**Готово (task.md):** фактичні права перевіряються на сервері, і недоступне не
потрапляє ні в API, ні в realtime, ні в контекст ШІ, пошук, експорт, перегляд
чи завантаження. Ілюстратор бачить сцену 17 і потрібних героїв, а не весь
рукопис; менеджер книги не отримує прав на канон.

## 1. Що вже є

- **Учасники й ролі** (Т6.1): `project_participants`, `participant_roles`,
  `collab_events`; роль нічого не дозволяє.
- **Доступ сьогодні — «все або нічого»**: власник (і адмін) — усе;
  прийняте запрошення — уся книга (пише всякий, крім читача).
  `resolveProjectAccess` (API ядра, 89 маршрутів `/api/projects/:id/*`) і
  `resolveRealtimeAccess` (кімната спільного редагування — повна книга в
  `room:sync`, `book:remote_update`, `section:remote_patch`).
- **Серверна копія книги й зібрані файли** (`/api/books/:id`, артефакти) —
  лише власник і адмін; запрошені їх не отримують уже зараз.
- **Медіатека** — лише свої файли (`/api/media/list`).

## 2. Рішення власника (01.10.2026)

1. **Чинні доступи — наданий доступ на всю книгу:** кожне прийняте
   запрошення стає доступом до книги з тими самими правами (дизайнер,
   видавець, перекладач — редагування; бета-читач — перегляд). Звужує надалі
   власник.
2. **Області зараз — книга, розділ, сцена, персонаж, локація, медіатека.**
   Стиль-біблія, завдання й результати — у моделі, застосування — у Т7.
3. **Усі канали:** кімната спільного редагування (обмежений учасник отримує
   й правит лише своє), серверна копія й експорт, API ядра (для обмеженого
   доступу закрито все, що не дозволено явно), контекст ШІ на сервері, пошук.
4. **Панель «Доступ» у «Команді» + API.** Надає власник, адмін або учасник
   із правом керування.

## 3. Задум

**Наданий доступ** (`access_grants`, міграція 0021): проєкт, учасник, рівень
(`view` < `comment` < `review` < `edit` < `create` < `approve` < `manage`;
`work` — робочий доступ до медіатеки: перегляд і власні завантаження),
область (`book`, `chapter`, `scene`, `character`, `location`,
`media_library`; у моделі — `style_bible`, `task`, `deliverable`) і її id,
`valid_from` / `valid_until`, відкликання, хто надав (людина чи система — не
AI), звідки (вручну, перенесене запрошення). Кожна зміна — подія в
`collab_events`.

**Фактичні права** (`server/core/collaboration/access.ts`): власник і адмін
— усе; інакше — об'єднання дійсних наданих доступів учасника. Рівень на
книгу покриває всі розділи, сцени й сутності; доступ до розділу — усі його
сцени. **Обмежений** доступ — коли на всю книгу немає навіть перегляду.
Прийняте запрошення без жодного запису доступу — один раз стає доступом на
книгу (рішення 1); після цього лише явні записи (відкликаний не
відновлюється).

**Застосування:**
- кімната: обмеженому учаснику — книга лише з дозволених розділів і сцен (і
  дозволених героїв у картках), без решти полів; його правки приймаються
  лише в сценах з правом редагування й не стирають решту книги; чужі
  точкові правки недозволених сцен йому не надходять; зміна доступу —
  перепідключення з новими правами;
- API ядра: обмеженому — лише явно дозволені читання (свій доступ, дозволені
  сутності, їхній візуальний канон, медіатека книги); решта — 403
  `scope_restricted` (пошук, граф, профілі з цитатами, допит, ШІ);
- медіатека книги: `GET /api/projects/:id/media` — файли власника (і
  учасників із робочим доступом) цієї книги, за доступом `media_library`;
- серверна копія книги й експорт — як і досі, лише власник і адмін (перевіряє
  тест).

**Критерії.** v3 №36 (доступ за областю) — записи з рівнем і областю, сервер

допущений; №11, 18, 20, 22 — надання, відкликання, строк, журнал. Creative —
недоступне закрите і в інтерфейсі, і в прямому API (403 `scope_restricted`,
обрізана книга кімнати).

**Чого ще немає — і чому.** Стиль-біблія, завдання й результати як області —
у моделі, застосування — Т7 (рішення власника). Коментування й рецензування
як окремі дії — рівні є, каналів ще немає (поки дають перегляд). Онбординг і
запит доступу — Т6.3; «Моя роль у проєкті» — Т6.4.
