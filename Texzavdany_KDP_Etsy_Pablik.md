## 1. Мета модуля

Дати автору можливість одним кліком підготувати готовий продукт (книгу, робочий зошит, міні-курс) до публікації на зовнішніх майданчиках — **Amazon KDP** та **Etsy** — без ручного форматування файлів і без ризику відхилення через невідповідність технічним вимогам платформи.

Модуль складається із трьох підсистем:

- **Генератор KDP-сумісних файлів** (експорт).
- **Пряма інтеграція з Etsy Open API v3** (публікація).
- **Пакувальник курсових компонентів** (агрегація робочих матеріалів у товар).

| Платформа | Публічний API для сторонніх розробників | Що це означає для нас |
|---|---|---|
| **Amazon KDP** | Відсутній. Немає офіційного способу опублікувати книгу програмно. | Модуль може лише згенерувати файли за специфікацією KDP. Фінальне завантаження в кабінет KDP виконує сам користувач вручну. |

## 3. Підсистема 1: Генератор KDP-сумісних файлів

### 3.1 Функціональні вимоги

Експорт готового тексту (з розділу «AI-редактор книги» / «Генератор структури книги») у формати:

- **EPUB** (реф-версія для Kindle, валідний за EPUB 3.0/epubcheck)
- **PDF** — версія для друку, з підтримкою трим-розмірів KDP: 5×8, 5.5×8.5, 6×9 дюймів
- **DOCX** — резервний формат для ручного редагування

Генерація обкладинки під KDP-специфікацію (розрахунок ширини корінця за кількістю сторінок, роздільна здатність ≥300 dpi, кольоровий профіль CMYK для друку / RGB для e-book).

Генерація KDP-метаданих-листа (не завантажується автоматично, а видається користувачу як довідка для копіювання в кабінет KDP): назва, підзаголовок, опис (до 4000 символів), 7 ключових слів, категорії BISAC.

Валідація перед експортом: перевірка мінімальної кількості сторінок, наявності змісту, коректності структури заголовків.

### 3.2 Технічна реалізація

- Використати існуючі бібліотеки конвертації (наприклад, ebooklib для EPUB, WeasyPrint/ReportLab для друкованого PDF з точним розрахунком трим-розміру та полів).
- Окремий сервіс `kdp-export-service`, що приймає структурований документ (JSON/HTML AST з внутрішнього редактора) і повертає готові файли.
- Асинхронна обробка через чергу завдань (наприклад, задача в Celery/BullMQ) — генерація друкованого PDF з обкладинкою може займати десятки секунд.
- **Ліміт розміру файлу рукопису KDP — 650 МБ** (обмеження Amazon); враховувати при генерації PDF з високороздільною обкладинкою.

### 3.3 AI-дисклеймер при публікації на KDP

> **Перевірено 31.08.2026:** Amazon KDP вимагає під час публікації позначити прапорцем, чи містить книга AI-згенерований текст, зображення або переклади. Оскільки контент на нашій платформі здебільшого створюється або суттєво генерується AI-редактором, **метадані-лист (3.1) має включати нагадування-чекліст із формулюванням цього питання**, щоб автор не забув відзначити відповідну галочку в кабінеті KDP — недотримання призводить до блокування публікації або видалення вже опублікованої книги.

- **AI-generated** (потребує дисклеймеру) — контент, який AI створив за промптом користувача, навіть після суттєвого редагування.
- **AI-assisted** (дисклеймер не потрібен) — контент, який написав сам користувач, а AI лише допомагав (брейншторм, редагування, перевірка граматики).
- Модуль може евристично позначати згенеровані розділи під час експорту, але фінальне рішення про дисклеймер завжди залишається за автором — Amazon вимагає точності, а не мінімізації.

### 3.4 Критерії приймання

- [ ] Згенерований EPUB проходить перевірку epubcheck без помилок.
- [ ] Друкований PDF відповідає обраному трим-розміру з точністю до 1 мм.
- [ ] Обкладинка має правильно розрахований корінець для заданої кількості сторінок і типу паперу.
- [ ] Метадані-лист містить усі обов'язкові поля KDP, включно з нагадуванням про AI-дисклеймер.

> **Перевірено 31.08.2026:** з кінця 2025 року денний ліміт KDP (3 книги/день) замінено на тижневий — **10 нових тайтлів на тиждень на кожен формат** окремо (eBook, paperback, hardcover), тобто до 30 тайтлів/тиждень при використанні всіх трьох. Ліміт рахує момент створення чернетки, а не публікації. Активним користувачам платформи варто показувати цей ліміт у UI, щоб вони не втрачали чернетки книг, підготовлених модулем.

## 4. Підсистема 2: Інтеграція з Etsy Open API v3

### 4.1 Обмеження платформи (враховані в дизайні)

- Максимум **5 цифрових файлів** на один лістинг, до **20 МБ кожен**.
- Дозволені формати цифрових файлів: .pdf .doc .zip .mp3 .mpeg .mov .epub .mobi .txt .rtf .png .jpg .jpeg .gif .bmp .psp .stl .iBook.
- **Назви файлів обмежені 70 символами** (літери, цифри, крапки, підкреслення, дефіси) — покупець бачить точно ту саму назву, редагування після завантаження неможливе.
- **Варіації (розміри, кольори) недоступні** для цифрових товарів.
- **Ліміт швидкості API: 10 запитів/секунду** на застосунок (з exponential backoff на 429/5xx).
- **Додатковий денний ліміт: 10 000 запитів/24 год** (ковзне вікно, а не фіксована північ-північ доба) — оцінюється після QPS; при перевищенні також повертається 429.
- Наслідок для курсів: повноцінний відеокурс не поміщається в ліміти Etsy → потрібна стратегія доставки контенту (див. 4.5).

### 4.2 Авторизація

1. Реєстрація застосунку в Etsy Developer Portal → отримання API Key (keystring) і Shared Secret.
2. OAuth 2.0 Authorization Code Grant + PKCE:
   - Скоупи: listings_r, listings_w, listings_d, shops_r, shops_w.
   - Redirect URI на бекенд нашого сайту (/api/etsy/oauth/callback).
3. Збереження access_token + refresh_token у зашифрованому вигляді (AES-256, окремий secrets-стор, не в основній БД користувача як plain text).
4. Автоматичне оновлення токена по refresh_token до закінчення терміну дії: **access_token живе ≈1 годину, refresh_token — ≈90 днів** — логіку фонового оновлення розраховувати саме під ці інтервали.

### 4.3 Рівні доступу до застосунку Etsy

> **Перевірено 31.08.2026 — критично для архітектури:** Etsy розрізняє три рівні доступу застосунку, і проста реєстрація (крок 1 у 4.2) сама по собі не дає права підключати магазини інших авторів.

- **Seller App** — доступ лише до одного власного магазину розробника, схвалення автоматичне за хвилини. **Не підходить нашій платформі** — вона працює з магазинами багатьох авторів.
- **Personal App** — доступ поза межами одного магазину, але в обмеженому масштабі; проходить поглиблену ручну перевірку Etsy.
- **Commercial Access** — саме цей рівень потрібен нам (доступ до магазину будь-якого автора, що дав OAuth-згоду). Отримати його можна лише *після* схвалення Personal App, окремим ручним комерційним рев'ю; термін розгляду Etsy не гарантує.

Вимоги Etsy до заявки на Commercial Access:

- Застосунок і його публічна сторінка відповідають Etsy API Terms of Use.
- Дотримання політики кешування даних (Section 1 API Terms of Use).
- На видному місці — фраза: «The term 'Etsy' is a trademark of Etsy, Inc. This application uses the Etsy API but is not endorsed or certified by Etsy, Inc.»
- Жодного скрейпінгу в обхід API.
- Доступ до приватних даних користувача — лише через OAuth.
- **Наслідок для дорожньої карти:** двоетапне узгодження (Personal App → Commercial Access) варто закласти в план релізу окремим блокуючим кроком, а не як частину звичайного онбордингу.

### 4.4 Основний потік публікації (happy path)

```
Користувач натискає «Опублікувати на Etsy»
        │
        ▼
[1] Перевірка підключення Etsy-акаунта
        │  (якщо не підключено → OAuth-флоу)
        ▼
[2] POST /v3/application/shops/{shop_id}/listings
        (createDraftListing: title, description, price,
         taxonomy_id, type="download", shop_section_id)
        │
        ▼
[3] POST .../listings/{listing_id}/images  (uploadListingImage)
        — обкладинка + до 9 додаткових превʼю-зображень
        ▼
[4] POST .../listings/{listing_id}/files  (uploadListingFile)
        — до 5 файлів, перевірка ≤20 МБ кожен
        |  якщо продукт більший — див. 4.5
        ▼
[5] PATCH .../listings/{listing_id}  (updateListing: state=active)
        ▼
[6] Збереження etsy_listing_id у нашій БД, показ користувачу
        посилання на живий лістинг
```

### 4.5 Стратегія для курсів (обхід ліміту 5 файлів/20 МБ)

Оскільки Etsy не призначений для доставки багатомодульних відеокурсів, модуль має пропонувати користувачу один із двох сценаріїв на етапі підготовки товару:

- **Сценарій А — «Etsy як вхідна лійка»:** на Etsy публікується PDF-путівник курсу з описом програми та унікальним лінком/кодом доступу до повного курсу на власній платформі (особистий кабінет автора). Основний контент лишається під контролем автора.
- **Сценарій Б — «Компактний курс»:** якщо курс невеликий (робочий зошит + аудіо-урок + шаблони), матеріали пакуються в один .zip ≤20 МБ і публікуються як єдиний цифровий товар.

Модуль автоматично оцінює сумарний розмір курсових компонентів і рекомендує сценарій А або Б.

### 4.6 AI-дисклеймер при публікації на Etsy

> **Перевірено 31.08.2026 (оновлено з січня 2026):** для лістингів, де генеративний AI суттєво сформував результат (зображення, опис, макет), Etsy вимагає одночасно:

- **прапорець «використовує AI»** на лістингу;
- **зміну атрибуції з «Made by [seller]» на «Designed by [seller]»** у виробничих полях лістингу.

Обидва поля потрібно виставляти програмно на кроці [2] потоку публікації (4.4, createDraftListing) — не лише зображення, а й опис і макет, згенеровані нашим AI-редактором, підпадають під цю вимогу. Пропуск дисклеймеру — підстава для видалення лістингу за Creativity Standards.

### 4.7 Обробка помилок і повторні спроби

- Коди 429/5xx → експоненційний backoff (базова затримка 1с, максимум 5 спроб).
- Код 401 → автоматичне оновлення токена через refresh_token, повтор запиту один раз.
- Часткова невдача (наприклад, зображення завантажено, файл — ні) → лістинг лишається в статусі draft, користувачу показується конкретна помилка з можливістю ручного довантаження.
- Ідемпотентність: перед створенням нового лістингу перевіряти, чи вже існує etsy_listing_id для цього товару в нашій БД, щоб уникнути дублів при повторному натисканні.

### 4.8 Критерії приймання

- [ ] OAuth-підключення Etsy-акаунта проходить і токен коректно оновлюється після закінчення терміну дії.
- [ ] Створений лістинг з'являється в кабінеті продавця Etsy зі статусом draft/active відповідно до вибору користувача.
- [ ] Спроба прикріпити 6-й файл або файл >20 МБ блокується на етапі підготовки з зрозумілим повідомленням користувачу (до звернення до API).
- [ ] При тимчасовій недоступності Etsy API (5xx) публікація автоматично повторюється і не губить дані користувача.
- [ ] Всі викликані дії відповідають ліміту 10 запитів/сек та 10 000 запитів/добу.
- [ ] Застосунок має схвалений Commercial Access від Etsy до релізу функції для будь-якого автора, окрім власного тестового магазину.
- [ ] Кожен лістинг, створений AI-редактором, коректно позначений прапорцем AI та атрибуцією «Designed by [seller]».

## 5. Підсистема 3: Пакувальник курсових компонентів

### 5.1 Функціональні вимоги

Формування єдиного товарного набору («компонентний сет») з елементів, уже наявних у профілі автора:

- Робочий зошит (PDF, генерується з блоку «Генератор навчального курсу»)
- Слайди/конспект уроку
- Чекліст або шаблон вправи
- Аудіо-урок (опційно, якщо є)
- Сертифікат виконання (шаблон PDF з підстановкою імені)

Пакувальник:

1. Збирає обрані компоненти в один .zip.
2. Перевіряє сумарний розмір під ліміт цільової платформи (20 МБ для Etsy; для власного сайту ліміту немає).
3. Генерує файл-опис вмісту набору (README.pdf) для покупця.

### 5.2 Критерії приймання

- [ ] Користувач може обрати довільну комбінацію компонентів і отримати готовий .zip.
- [ ] Система попереджає, якщо розмір набору перевищує ліміт обраної платформи публікації, і пропонує сценарій А з розділу 4.5.

## 6. Підсистема 4: Etsy Keyword & Trend Research (дослідження попиту та SEO)

### 6.1 Важливе обмеження — прочитати перед проєктуванням

> **Etsy Open API v3 не надає ні даних про продажі чужих лістингів, ні готового підбору SEO-ключових слів, ні позиції в пошуковій видачі.** Це підтверджено офіційною спільнотою розробників Etsy.
>
> Тому «дослідження бестселерів» і «SEO-підбір слів» у нашому продукті — це власна аналітична надбудова над обмеженим набором публічних даних API, а не пряма функція Etsy.

| Що потрібно бізнесу | Чи є в Etsy API напряму | Наш обхідний підхід |
|---|---|---|
| Кількість продажів товару-конкурента | ❌ Немає такого поля | Проксі-метрика: num_favorers (кількість «улюблених», є в API) + давність лістингу + позиція серед топ-N результатів пошуку |
| Позиція в пошуковій видачі за ключовим словом | ❌ Не експонується | Побудова власного «зрізу»: періодичний запит findAllListingsActive з keywords=...&sort_on=score і фіксація порядку відповіді як приблизного ранжування на момент запиту |
| Підбір SEO-ключових слів | ❌ Ендпоінта немає | Частотний аналіз слів/біграм у заголовках і тегах топ-N активних лістингів за темою (NLP-обробка на нашому боці) |
| Тренд попиту за категорією/тегом | ❌ Немає | Порівняння count (загальна кількість активних лістингів) і середнього num_favorers по вибірці за кілька тижнів — власний часовий ряд |

### 6.2 Функціональні вимоги

- **Дослідження теми:** користувач вводить тему/нішу книги або курсу → система виконує серію запитів GET /v3/application/listings/active з релевантними ключовими словами та taxonomy_id, збирає до 100–200 топових активних лістингів.
- **Оцінка популярності:** для кожного лістингу фіксуються title, tags, num_favorers, price, creation_timestamp. Обчислюється «індекс популярності» = зважена комбінація num_favorers і позиції в результатах (не є офіційним рейтингом продажів — позначається в інтерфейсі як «оцінний показник», щоб не вводити користувача в оману).
- **Підбір ключових слів:** з масиву заголовків і тегів топових лістингів виконується частотний аналіз (токенізація, видалення стоп-слів, підрахунок біграм) → видається список кандидатів у теги (Etsy дозволяє до 13 тегів на лістинг, кожен ≤20 символів).
- **Історизація:** дані зберігаються з датою збору, щоб згодом показувати динаміку (зростає/спадає кількість пропозицій і середня «популярність» за темою).
- **Прозорість для користувача:** в інтерфейсі обов'язково явно вказати, що показники — оцінні (на основі публічно видимих сигналів), а не офіційна статистика продажів Etsy.

### 6.3 Технічна реалізація

- Окремий сервіс `etsy-research-service`, що працює за розкладом (cron / scheduled job), а не в реальному часі при кожному запиті користувача — щоб укластися в ліміт 10 запитів/сек і не навантажувати основний публікаційний флоу.
- Кеш результатів дослідження теми на 24–72 години (пошукова видача Etsy не змінюється настільки швидко, щоб виправдати запит на кожен клік користувача).
- NLP-обробка (токенізація, стоп-слова, біграми) — стандартна бібліотека (наприклад, nltk/spaCy для англомовних тегів; врахувати, що Etsy — переважно англомовний ринок, тому дослідження тем варто виконувати з англійськими ключовими словами навіть для україномовних авторів).
- Обмеження очікувань у продукті: чітко документувати для користувача, що це оцінка на основі публічних сигналів, а не гарантований прогноз продажів.

### 6.4 Критерії приймання

- [ ] За введеною темою система повертає список із щонайменше 20 релевантних активних лістингів з полями title, tags, num_favorers, price.
- [ ] Формується ранжований список кандидатів у SEO-теги (до 13 штук, кожен ≤20 символів) на основі частотного аналізу.
- [ ] Інтерфейс явно позначає показники як оцінні/непрямі, без формулювань на кшталт «бестселер» чи «продажі».
- [ ] Повторний запит тієї самої теми впродовж 24 годин повертає закешований результат, а не новий виклик API.
- [ ] Дослідницькі запити не впливають на ліміт швидкості публікаційних викликів (окрема черга/токен-бакет).

## 7. Модель даних (спрощено)

```

 ├─ id

Publication
 ├─ platform: enum [kdp, etsy]

 ├─ external_id  — etsy_listing_id (якщо platform = etsy)
 ├─ last_synced_at
 └─ error_log
```

## 8. Нефункціональні вимоги

- **Безпека:** OAuth-токени Etsy шифруються at rest; доступ до сервісу публікації — тільки від імені автентифікованого власника товару.
- **Спостережуваність:** логування кожного виклику Etsy API (без чутливих даних токена) для діагностики відхилених публікацій.
- **Відмовостійкість:** черга завдань публікації повинна переживати рестарт сервера без втрати статусу задачі.
- **Відповідність ToS Etsy:** заборонено використовувати автоматизацію, що імітує дії покупця (боти, накрутка обраного); модуль працює виключно в межах офіційного seller-facing API.

## 9. Поза межами цього ТЗ

- Публікація на інших маркетплейсах (Gumroad, Podia, Payhip) — окреме ТЗ за потреби.
- Автоматичне завантаження в кабінет Amazon KDP (технічно неможливо без порушення ToS Amazon — офіційного API немає).
- Оплата/виплати через Etsy Payments — керується самою Etsy, поза відповідальністю нашого модуля.
- **Гарантований прогноз продажів або офіційна аналітика бестселерів Etsy** — не існує джерела даних, здатного це забезпечити; підсистема 4 дає лише оцінні непрямі показники.
