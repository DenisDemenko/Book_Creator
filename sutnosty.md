# Сутності проєкту Book_Creality

Реєстр предметних сутностей застосунку. Джерело істини — `src/types.ts`;
цей файл описує, **що означає** кожна сутність для письменника і де вона живе.

Позначки: ✅ реалізована · 🧩 спроєктована, ще не реалізована

---

## 0. Реєстр ядра: 118 типів сутностей (задача #227)

Документ власника `Fusion_Lab_Studio_Entity_Registry_with_Literary_Critic_UA_EN.pdf`
(10 стор., звірено 22.09.2026) перенесено в код і в базу. **Він і є джерелом
істини для тегів**; таблиці нижче в цьому файлі лишаються описом того, що
означає кожна сутність Студії.

| Що | Де |
|---|---|
| Код-реєстр: 118 типів + 37 типів зв'язків + 12 груп | `src/utils/coreEntities.ts` |
| Таблиці бази, засіяні цим кодом | `server/db.ts` → `core_entities`, `core_entity_relations` |
| Читання й згадки в чаті | `server/coreEntityStore.ts` |
| HTTP | `GET /api/core/entities`, `/api/core/chat/sessions/:id/entities`, `/api/core/entities/:slug/sessions` |

Склад реєстру: **88** базових типів у 9 групах (A–I) + **30** типів додатка
«Літературна критика» (J1–J3) = **118**. Зв'язки: 21 базовий + 16 критичних = 37.

**Формат тега.** Документ описує його як `/сутність:назва` (приклад власника:
`/character:Serhii`). У тексті книги маркер загорнутий у квадратні дужки —
`[/character:Serhii]` — з тієї ж причини, що й `[^1]`, `[IMG: …]`, `[QR: …]`:
без межі тег неможливо ні знайти, ні безпечно зняти на експорті. Дужки —
не частина формату власника, а межа навколо нього.

**Теги не потрапляють у PDF** (пункт 6 постановки) — знімаються у трьох
шляхах експорту: `server/pdf/bookToMarkdown.ts`, `server/pdf/pdfRenderer.ts`,
`src/utils/helpers.ts`.

# 🧩 Спроєктовані сутності (ще не реалізовані)

Нижче — сутності, яких бракує в моделі. Кожна описана так, щоб її можна було
реалізувати без додаткового проєктування.

## A. Локація — `Location`

**Навіщо.** Зараз місце дії — це рядок `Scene.location`. Тому одне й те саме
місце пишеться щоразу заново, не має опису, атмосфери й ілюстрації, і його
неможливо знайти («усі сцени в лабораторії»). Для художньої книги локація —
друга за важливістю сутність після героя.

```ts
export interface Location {
  id: string;
  bookId: string;
  name: string;
  nameEn?: string;
  kind: 'city' | 'building' | 'room' | 'nature' | 'vehicle' | 'virtual' | 'other';
  /** Ієрархія: «Лабораторія» всередині «Верхнього Печерська». */
  parentLocationId?: string;
  description: string;
  atmosphere: string;      // запахи, звуки, світло — те, що йде в текст
  significance: string;    // чому це місце важливе для сюжету
  imageUrl?: string;
  tags: string[];
}
```
**Зв'язки:** `Book.locations: Location[]`; у `Scene` поле `location: string`
замінюється на `locationId?: string` зі збереженням старого рядка як запасного.

## B. Репліка — `DialogueLine`

**Навіщо.** Репліки зараз існують лише як текст. Через це неможливо порахувати,
скільки говорить кожен герой, перевірити впізнаваність голосу персонажа,
зібрати всі його репліки чи експортувати діалоги окремо.

```ts
export interface DialogueLine {
  id: string;
  sectionId: string;
  characterId: string;
  /** Порядковий номер репліки в розділі. */
  order: number;
  text: string;
  /** Ремарка: «тихо», «не підводячи очей». */
  beat?: string;
  emotion?: string;
  /** Зсув у `Section.content`, якщо репліка прив'язана до тексту. */
  offset?: number;
}
```
**Компроміс, який треба вирішити при реалізації:** або репліки лишаються
похідними від тексту (парсяться з рядків, що починаються з «—»), або стають
самостійними записами, а текст збирається з них. Перший шлях безпечніший і не
ламає наявний редактор.

## C. Сюжетна лінія — `PlotThread`

**Навіщо.** Немає способу побачити, чи всі лінії доведені до кінця. Класична
причина «провислих» ліній у чернетці.

```ts
export interface PlotThread {
  id: string;
  bookId: string;
  title: string;
  kind: 'main' | 'subplot' | 'romance' | 'mystery' | 'character-arc';
  question: string;        // драматичне питання лінії
  status: 'open' | 'developing' | 'resolved' | 'abandoned';
  resolution?: string;
  characterIds: string[];
  /** Сцени, у яких лінія рухається. */
  sceneIds: string[];
}
```

## D. Подія таймлайну — `TimelineEvent`

**Навіщо.** `Scene.timelineOrder` задає лише порядок сцен у тексті. Немає
внутрішньохронологічного часу світу — тому флешбеки й паралельні лінії
неможливо перевірити на суперечності.

```ts
export interface TimelineEvent {
  id: string;
  bookId: string;
  title: string;
  /** Час у світі книги — рядком, бо світ може бути вигаданим. */
  storyDate: string;
  /** Числовий ключ для сортування подій між собою. */
  sortKey: number;
  sceneId?: string;
  characterIds: string[];
  locationId?: string;
  isFlashback?: boolean;
}
```

## E. Предмет / артефакт — `StoryObject`

**Навіщо.** Ключові предмети («протокол Оберіг», нейроносій) зараз живуть лише
в тексті. Немає обліку, де предмет з'явився і де востаннє згадувався.

```ts
export interface StoryObject {
  id: string;
  bookId: string;
  name: string;
  description: string;
  significance: string;
  ownerCharacterId?: string;
  firstAppearanceSceneId?: string;
  imageUrl?: string;
  tags: string[];
}
```

## F. Термін світу — `GlossaryTerm`

**Навіщо.** У фантастиці й фентезі є власна лексика. Зараз вона розсипана між
сносками та власним словником перевірки, але без єдиного глосарію з
визначеннями — і читач, і сам автор плутаються.

```ts
export interface GlossaryTerm {
  id: string;
  bookId: string;
  term: string;
  termEn?: string;
  definition: string;
  /** Показувати в кінці книги окремим розділом. */
  includeInBookGlossary: boolean;
  relatedCharacterIds?: string[];
  relatedLocationIds?: string[];
}
```
**Примітка:** частково перетинається з `Footnote` і `customDictionary` —
при реалізації варто зробити глосарій джерелом для обох, а не четвертим
незалежним списком.

## Порядок реалізації (рекомендований)

1. **Локація** — найбільша віддача, найменший ризик; уже є куди підключити (`Scene`).
2. **Глосарій** — прибирає наявне дублювання між сносками й словником.
3. **Сюжетна лінія** — дає перевірку «чи все доведено до кінця».
4. **Репліка** — найбільший ризик для редактора, робити після рішення про похідність.
5. **Таймлайн** і **Предмет** — за потреби конкретної книги.
