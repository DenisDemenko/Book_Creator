# Т7.6 — окремий ручний прогін Visual Bible і Style Bible

Це сценарій для production після деплою, не звіт про вже виконані входи. Використовуйте окрему тестову книгу; не змінюйте канон робочої книги. Перед деплоєм збережіть резервну копію SQLite з WAL і persistent media. Спільний SQLite і Core мають бути доступні.

1. **Вхід і адреси.** Увійдіть власником `tropazemli@gmail.com`; відкрийте `/studio/creative/bible/<ID-книги>`, потім `/studio/creative/style/<ID-книги>`. Перевірте пряме відкриття / оновлення адрес, посилання з Workspace і «Походження» медіатеки.
2. **Передумови.** Створіть тестового персонажа й локацію. Завантажте різні референси, вкажіть AI/manual походження, затвердьте потрібні файли. Для героя створіть і затвердьте версію зовнішності. У «Прив’язки» медіатеки підтвердьте портрет саме цієї версії героя; для локації — її зв’язок. Незатверджений файл у виборі канону не з’являється; сам APPROVED ще не CANON.
3. **Стиль.** На Style Bible створіть «Нічний синій»: жанр, настрій, палітри, світло, заборонені кольори / стилі, композиція, зона заголовка. Кнопка збереження заблокована без підтвердження. Збереження не активує автоматично. Підтвердьте активацію й перевірте активну v1 після перезавантаження.
4. **Герой.** Окремо виберіть точний approved файл, персонажа, підтверджений зв’язок / версію зовнішності. Заповніть ракурс, вираз, одяг, вік, ключові ознаки, заборонені зміни; позначте головний образ. Перевірте окремий checkbox. Додайте до канону; у картці має бути зображення, версія файла, правила, хто / коли додав, стиль v1. У медіатеці — CANON та подія історії. Спроба створити другий головний образ тієї самої сутності дає конфлікт, не змінює його статус.
5. **Локації й інші категорії.** Додайте day/night/interior/aerial референси окремими записами; вкажіть час доби, сезон, погоду, освітлення, матеріали, архітектуру, ключові / заборонені елементи. Сценові прив’язки задайте до канонізації в provenance. Перевірте предмет / костюм / палітру / обкладинку та приватне відкриття оригіналу. Неправильна сутність або зв’язок іншого файла відхиляються.
6. **Два учасники.** В іншому браузері увійдіть як письменник `dahindaniel@gmail.com` або дизайнер `zhdanova9301@gmail.com`. Без grants Bible закритий. Надайте VIEW Visual Bible та Style Bible з ID тестової книги, окремо доступ до одного героя і його файла. Учасник бачить тільки героя, не приховану локацію / її файл / аудит / рукопис. VIEW не дає кнопок змін. Перевірте видавця `fusionlabstudio2026@gmail.com` без цих grants — доступ відсутній незалежно від ролі.
7. **Делегування й відкликання.** Надайте одному учаснику MANAGE Visual Bible, не MANAGE Style Bible. Він може підтвердити додавання дозволеного файла; автор події — цей учасник. Зміна стилю залишається закритою. MANAGE лише на книгу не замінює дозволу Bible. Відкличте module / entity / asset grant: наступний API-запит відмовляє / прибирає відповідний матеріал; UI прибирає картки при наступному polling до 5 с. Прямий приватний URL файла перевірте без інших прав на медіатеку / книгу.
8. **Конфлікти.** У двох вкладках відкрийте однакові дані. Одночасно додайте той самий файл: один успіх, другий конфлікт, один запис аудиту. Одночасно активуйте різні стилі з однаковою ревізією: один успіх, другий конфлікт.
9. **Незмінність стилю.** Візьміть v1 за основу нової v2, змініть палітру / світло й активуйте. Старий канонічний герой, файл, approval, зовнішність і прив’язаний стиль v1 лишаються без змін. Новий канонічний запис фіксує v2. «Показати структурований контекст» повертає поточний стиль і тільки дозволені референси; перевірте під двома акаунтами.
10. **Вилучення.** Спробуйте змінити provenance / видалити CANON звичайною медіатекою — відмова з поясненням. Вилучіть у Visual Bible: обов’язкові окрема причина й підтвердження. Файл повертається APPROVED, не зникає; аудит зберігає старий запис, автора й причину. Повторний застарілий запит дає конфлікт. Новий образ можна додати окремою дією.
11. **Стійкість і мобільний.** Перезапустіть тестовий deployment без очищення тому: канон, стилі, активна версія, походження й аудит зберігаються. На телефоні перевірте картки / форми / відкриття файлів / контекст, без горизонтального прокручування. При зміні акаунта дані попереднього користувача не мають залишатися.

Автоматично: `npm run test:creative-bible`, `npm run test:creative-bible -- --browser`, ізольований Core PostgreSQL через `CORE_TEST_DATABASE_URL`; також повні `npm test`, `npm run lint`, `npm run build`. Auth seam тестів не підтверджує production Firebase, Railway, cookies або фактичний deployment. Платні AI виклики й task-specific style override — Т7.7.
