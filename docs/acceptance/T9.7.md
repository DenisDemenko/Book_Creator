## Підготовка після деплою

Створити окрему тестову книгу й карту з трьома героями на двох рівнях.
Один герой знає секрет; інші його не знають. У двох героїв мають бути
різні місця підтримки важеля, який відкриває міст. Зберегти карту й явно
відкрити версію всіх трьох героїв для читачів.

Через наявну співпрацю надати трьом тестовим обліковим записам перегляд
цілої книги. Автор створює групу; учасники заходять окремими профілями
браузера. Один обирає кандидатуру у співавтори, двоє — звичайну участь.

Вхід: меню Studio → Читач лабіринта → Групове проходження.
Прямий маршрут після деплою:
https://www.fusionlab.in.ua/studio/projects/PROJECT_ID/labyrinth-reader
До посилання групи додаються параметри labyrinth=group та groupRun=ID.
Саме посилання не надає доступу.

## Сценарії

1. [ ] Автор бачить лише учасників із чинним переглядом книги.
   Вимкнений акаунт і стороннього не можна призначити.
   Чернетку карти не можна використати замість відкритої версії.

2. [ ] Запрошення видно лише призначеному користувачу. До прийняття
   секрети героя не видаються. Він сам вибирає псевдонім, режим участі
   та підтверджує умови. Кандидатура не означає остаточного співавторства.

3. [ ] Автор запускає гру після готовності всіх учасників.
   Гість, звичайний учасник або сторонній за прямим URL її не запускає.
   Автор, який не призначений герою, не керує його ходами.

4. [ ] Перевірити три сцени, обидва рівні й маркери. Секрет першого героя
   відсутній у DTO, DOM, кеші та JavaScript інших. У браузерних Network
   перевірити відсутність повної карти, чужих станів і trace директора.
   Уже наданий перегляд рукопису цим модулем не звужується.

5. [ ] Діє авторський порядок ходів. Спроба надіслати heroId іншого героя,
   віддалений objectId чи довільну подію не змінює гру.

6. [ ] Два вікна того самого учасника одночасно роблять хід з однієї
   ревізії: один прийнятий, другий конфлікт. Час і наслідок змінені один раз.
   Оновлення показує актуальне своє місце.

7. [ ] Створити небезпеку на верхньому рівні. Хід героя знизу просуває
   спільний час і враховує шкоду герою згори. Небезпечна зміна без
   доведеного шляху для всіх активних героїв не приймається.

8. [ ] До зайняття місць підтримки важіль не виконується. Звичайний
   interact не обходить голосування. Після згоди всіх важіль працює один
   раз і відкриває маршрут до зустрічі героїв.

9. [ ] Окрема група з правилом більшості: 2/3 достатньо для спільної дії;
   заперечення враховане. Дублі голосів і старе decisionId не змінюють світ.
   Назва віддаленого механізму не розкривається герою в іншій кімнаті.

10. [ ] За замовчуванням група чекає без таймера. В окремому проходженні
    ввімкнути дозволений пропуск: раніше строку він закритий, після —
    передає чергу без руху чужого героя й без витрати часу історії.

11. [ ] Призначити одного автономного FLC. Його окрема кнопка виконує
    перевірений локальний хід або передає чергу. Вона не керує людським
    героєм і не створює платний виклик чи непогоджений текст.

12. [ ] Чат гравців бачить група. Діалог героя бачать тільки герої поруч
    під час надсилання. Пізніша зустріч не відкриває старого діалогу.
    Текст із HTML показується текстом; жодний чат не додається до внесків.

13. [ ] Кандидат подає окремий текст. Без прапорця згоди він не потрапляє
    до журналу. Автор бачить псевдонім, місце, час, версію та заявлену
    участь ШІ. Звичайний читач не пише внески за іншого користувача.

14. [ ] Власний внесок відкликається й зникає з авторського журналу.
    Чужий відкликати не можна. До журналу не потрапляють приватні діалоги,
    усі знання героя або непогоджені чернетки.

15. [ ] Втратити відповідь після прийнятого запиту й натиснути
    «Повторити запит»: та сама дія або повідомлення записані один раз.
    Перезапуск сторінки та сервера відновлює стан і небезпеку.
    Вбудований читач після reload лишається у груповому режимі.

16. [ ] Повернення до checkpoint вимагає одностайності навіть у групі
    з правилом більшості. Відновлено час, ресурси, туман і фактичні рішення
    Jev; історія лишилась. Відкликані права та згода на внесок не відродились.

17. [ ] Відкликати grant або вимкнути акаунт під час відкритої гри.
    Наступний запит закритий, WebSocket відключений і сцена прибрана.
    Оновлення активними учасниками скасовує голосування з вибулим виборцем
    без зміни часу або застосування його наслідку.
    Після фіксації виходу новий grant не повертає стару участь.
    Відкликання видання закриває всі групи; повторне відкриття не оживляє їх.

18. [ ] Пройти з клавіатури, реального телефона 390 px і екранного читача.
    Перевірити фокус, мітки форм, більший текст, текстову карту та відсутність
    горизонтального прокручування. Перевірити справжній production proxy,
    WebSocket/Firebase і перезапуск Railway з PostgreSQL. Канон книги
    й збереженої карти не повинен змінитися через проходження.
