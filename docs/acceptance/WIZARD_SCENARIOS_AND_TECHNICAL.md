## Що доступно

У книжковому майстрі відокремлено спосіб початку книги від моделі розвитку та добровільних прийомів.

| Спосіб початку | Вхід і правило |
|---|---|
| Задум | Головне питання, конфлікт і ставки |
| Конфлікт | Сторони, несумісні цілі, ціна рішення |
| Світ / локація | Правила світу та порушення рівноваги |
| Готові матеріали | Завантажені й підтверджені уривки; прогалини відокремлені від фактів |
| Реальний досвід | Події, псевдоніми, межі розкриття, підтвердження дозволу |
| Герої та фотографії | Ручні картки, приватні фото, явний аналіз видимого та затвердження опису |
| Інтерв’ю | Структуровані відповіді: тема, початок, перелом, приклад, висновок, дія читача |
| Продовження серії | Імпорт героїв і тексту поточної книги, незавершені лінії, часовий стрибок, новий конфлікт; результат в окремій книзі |
| Детектив від розгадки | Незмінна істина, докази, хибні версії та час розкриття |
| Книга-лабіринт | Місця, переходи, фінали; вибори й наслідки зберігаються в рукописі |
| Спільна книга | Учасники, авторство внесків, дозволені джерела, редакційні домовленості |
| Практична книга | Аудиторія, проблема, результат, підтверджені приклади та вправи |

Моделі розвитку: шлях змін героя; зіткнення характерів і цілей; зміна станів і цінностей; зміна сприйняття; документальна тема, досвід і висновки. Кожна має шість конкретних переходів, які передаються в промпти. Ведична й буддійська оптики є літературними прийомами. Польті та природні мотиви вмикаються окремо. Кількість героїв задає автор; нонфікшн можна пройти без героїв.

ШІ отримує поля вибраного сценарію, канон героїв, авторську дугу, підтверджені матеріали, загальний план та попередні частини. Новий склад героїв показується окремою пропозицією: додати, замінити, ігнорувати. Перед структурою автор перевіряє синопсис і план; перед передачею до редактора — глави. Ручний маршрут доступний без ШІ.

## Окремий технічний сценарій

Вибір напряму → «Інструкція з фото й техдокументації».

1. Виріб, точна модель/ревізія, завдання, тип: складання або використання.
2. Камера або JPG/PNG/WEBP; документи PDF/DOCX/TXT/MD; ручний текст.
3. Пошук документації з необов’язковим обмеженням доменом виробника; імпорт публічного HTTPS HTML/тексту/PDF. Є окреме посилання на пошук у браузері, якщо серверний пошук недоступний.
4. Перевірка витягу, моделі й ревізії. Кожне джерело спочатку непідтверджене.
5. Явна генерація пропозиції: деталі, інструменти, застереження, залежність кроків, критерій виконання, точні джерела кожного кроку й питання для уточнення.
6. Явне прийняття в наявний редактор інструкцій. Кожен AI-крок потребує перевірки автором; зміна його змісту скидає підтвердження.
7. Передача до нової книги. Походження й назви джерел зберігаються, додаткове автоматичне переписування ШІ вимкнене.

Аналіз фото запускається лише окремою кнопкою з вибраною доступною моделлю із зором. Опис фото можна ввести вручну. Фото не використовується для визначення особистості, характеру чи невидимих технічних характеристик. Власник погоджує зовнішність героя або технічні спостереження.

Ліміти: 8 МБ на файл, 100 000 символів на джерело, 20 джерел, 600 000 символів на чернетку. Текстовий PDF читається наявним extractor, DOCX — mammoth. Скан без тексту пропонується обробити наявним OCR або додати як фото; нового OCR немає.

Після деплою прямий вхід: https://app.fusionlab.in.ua/studio/?open=express&wizard=technical_instruction . Наявність цих змін на опублікованому сайті в цій сесії не підтверджена.

## Цілісність і доступ

Чернетка має revision/CAS; переходи чекають збереження, помилка запису зупиняє залежну генерацію. Правки синхронно резервуються в sessionStorage, конфлікт не затирає локальну копію. Нові ID героїв не залежать від позиції в масиві. Власну чернетку після входу читає лише її власник.

Приватні фото використовують наявну медіатеку. Власника перевіряють до та після AI-виклику; пізня відповідь не записується після відкликання джерела чи зміни ревізії. Непідтверджений текст не передається ШІ. Запити позначено privateContent; сирі приватні джерела й фото не публікуються через перенесення книги.

Вебімпорт приймає лише публічний HTTPS, перевіряє DNS та кожне перенаправлення, закріплює адресу з’єднання й обмежує час/розмір відповіді. Авторські інструкції в імпортованому тексті не стають системними командами.

## Перевірка

Відтворювані команди:

- npm run test:express-draft-session
- npm run test:wizard-scenarios
- npm run test:wizard-scenario-routes
- npm run live:wizard-scenarios
- npm run lint
- npm run build

API-прогін використовує справжні маршрути, SQLite й медіасховище. У браузерному прогоні відкривається повний App.tsx із CSS/брендом/фоном Студії на 390 та 1440 px. Ідентичність, AI-відповіді та зовнішні вебсторінки є контрольованими fixtures. Це перевірка з’єднання компонентів, прав і даних; якість реального AI та доступність зовнішнього пошуку перевіряються окремо.

Реальний зовнішній прогін Arduino/Bing у цій хмарі заблокований DNS: getaddrinfo EAI_AGAIN / тайм-аут DNS. Імпорт доступних публічних сайтів і реальні результати пошуку потрібно підтвердити в оточенні деплою; локальні fixtures цього не підтверджують.

Фінальний прогін: **171 цільова перевірка** (27 чернетки, 83 контракти сценаріїв, 61 API), **15 браузерних перевірок**, 4 екрани, 0 помилок JavaScript/горизонтального overflow; типи й збірка exit0. Перевірено запис джерела понад 64 КБ у справжній SQLite, claim гостьової чернетки перед AI, повторне погодження після регенерації та збереження AI-походження після правок.
Повний npm test також пройшов до останніх вузьких уточнень; після них повторено всі пов’язані suites, браузер, типи й збірку. На GitHub Actions цей незакомічений стан не запускався. [Машинний звіт і SHA-256 перевірених файлів](../reports/WIZARD_SCENARIOS_IMPLEMENTATION_2026-10-15.evidence.json). Деталі — запис #439 журналу.

## Межі цього етапу

Це робочі входи та побудова книги, а не нові окремі ігрові/колаборативні рушії. Сценарій лабіринта зберігає текстові вибори, але ще не імпортує їх автоматично в runtime-граф. Спільна книга збирає дозволені внески; вона не надсилає запрошень і не замінює наявні договори співавторства. Інтерв’ю тут є структурованою анкетою; окремий наявний interview-модуль не перебудовувався.

Повний новий Story Entity/Visual Bible, новий генератор картинок, автоматична перевірка достовірності документації, CAD-розпізнавання з фото, автономне сертифікування технічної інструкції — поза цим етапом. Також відкриті інші роботи A–H: вибраний рушій у розвороті, media-aware pagination, JEV arc/enrichment, CoverConfig, pageMap та zoom/Fit.
