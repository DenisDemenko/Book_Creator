# Т8.3 — живе приймання біржі творчих замовлень

Макет: Stitch 9 `fusion_lab_creative_studio`. Каталог і заявки — Marketplace; шестикроковий майстер приватного брифу — Studio. Т7.3 вже реалізовано, тому анонс PLANNED не потрібний. Цей сценарій ще потрібно пройти на production після деплою обох репозиторіїв.

## Каталог, дві мови й мобільний

1. Відкрити `/creative-orders` та `/en/creative-orders` гостем. Звірити герой, чотири інформаційні клітинки, картки, Scope ACL, шість кроків і прозорі умови. Число завдань відповідає API та поточним фільтрам. Чернетки й MODERATION не показуються.
2. Перевірити пошук за реальною назвою, категорії-чипи та select, статус і AI policy. «Усі фільтри» відкриває бюджет/умови як текст, формат, дату й мову. Ввести поєднання без результатів, перевірити порожній стан; «Скинути» очищає поля й повертає OPEN. Чип категорії застосовує поточні поля разом із типом. Фільтри зберігаються лише в поточній сторінці, не в URL.
3. Перевірити 390×844: відсутність горизонтального прокручування, доступність кнопок, полів, карток і всіх шести кроків. Перевірити клавіатуру, видимий focus, aria-pressed та aria-expanded.
4. Зображення карток — підписані ілюстрації категорій, а не результати роботи авторів. Умови бюджету текстові. Платформа не обіцяє escrow, гарантій оплати або автоматичних прав на книгу.
5. Вимкнути мережу API й натиснути «Оновити»: має бути видима помилка. Повернути мережу й повторити, перевірити відновлення. Гостю «Мої замовлення/заявки» пропонують увійти.

## Шестикроковий майстер Studio

6. Увійти автором, відкрити книгу → Спільна робота → Творчі проєкти. Створити проєкт та відкрити його бриф. Крок 1 показує саме обрану книгу й проєкт; іншій книзі потрібен окремий творчий проєкт.
7. Крок 2: вибрати тип роботи. Крок 3: заповнити назву, завдання, результат, формат, розміри, стиль, публічні референси й мову. За бажанням використати DeepSeek для AI-чернетки; відповідь не повинна зберігатися чи публікуватися сама. Реальний платний виклик перевіряється окремо від тестового провайдера.
8. Крок 4: вибрати мінімальні матеріали й рівні Scope ACL. NONE за замовчуванням. Крок 5: бюджет, вихідні файли, концепти, раунди правок, строк і AI policy. Зберегти приватний бриф і scope явно. Перехід «Далі/Назад» та прямі переходи кроків не зберігають і не публікують.
9. Крок 6: якщо зміни не збережені, перегляд збереженого брифу заблокований. Перевірити всі публічні поля. Без прапорця підтвердження надсилання заблоковане. Підтвердити й надіслати; MODERATION ще не відкриває каталог. Рукопис і scope не входять до публічного snapshot.
10. «Усі поля» повертає повну форму без втрати незбережених значень; повторне натискання повертає майстер. Окремий блок надання реальних прав залишається окремим від кроків публікації.
11. Модератор схвалює бриф у Marketplace. Автор перевіряє «Мої замовлення», а гість — публічний каталог. Нові чернетки не підміняють підтверджений snapshot автоматично.

## Заявки, вибір і приватність

12. Увійти схваленим дизайнером (реальний тестовий акаунт Яни — за її авторизацією). Подати повідомлення, публічні роботи, дату, умови й розкриття AI. Перезавантажити — заявка збережена. Оновити, відкликати та подати знову. Несхвалений профіль не отримує доступу до подання.
13. Увійти автором: порівняти реальні заявки, строки, умови й роботи. Вибрати заявку. Без окремого підтвердження кнопка вибору заблокована. Підтвердити — статус SPECIALIST_SELECTED, а книга не відкривається автоматично.
14. У другій вкладці спробувати застарілий вибір/запис: 409 не повинен перезаписати вже прийняте рішення. Оновити сторінку й звірити поточну ревізію.
15. Гостем та стороннім користувачем відкрити той самий URL: приватні повідомлення й умови заявки не видно. Змінити акаунт у відкритій вкладці — попередні власні матеріали не повинні показуватися новому користувачеві.
16. У Studio синхронізувати вибір. Перевірити Workspace лише після явного надання мінімальних матеріалів, потім відкликати доступ. Це регресія Т7.3–Т7.4; вибір на біржі сам не створює grants.

Записати URL/час, обидва commit SHA, ролі, кроки та результат без паролів, токенів або приватних рукописів. Local Chromium та тестова ідентичність не замінюють production Firebase/bridge приймання.
