# Т9.5 — вісім дворівневих механік: ручне приймання

**Реалізовано локально 12.10.2026. Production/Firebase-приймання: НЕ ВИКОНАНО.**

Локальна перевірка: модель/наслідки **36/0**, приватний API/PostgreSQL **49/0**, Chromium **20/0**. Всі вісім пройшли додавання до чернетки, збереження, попередження, активацію та відповідь; природне завершення, поєднання й останній шлях порятунку перевірені поведінковими тестами. Повний `npm test`, типи й production build успішні; це не перевірка реальних облікових записів або Railway.

## Передумови й спільний цикл

1. Записати активний deployment SHA/URL, акаунт і час. В окремій тестовій книзі відкрити **Конструктор структури → Книга-лабіринт → Дворівневий приклад**. Не підміняти робочу карту без згоди.
2. У «Бібліотека механік · 8 шаблонів» вибрати механіку, міст із нижніми вузлами та місце відповіді. Для ілюзії це початок мосту; для решти — нижній вузол. Налаштувати підготовку/тривалість/паузу/шкоду.
3. Натиснути «Додати механіку до чернетки». До збереження немає нової серверної версії чи нового прогону. Переглянути попередження, обхід, прив’язку, умови й відповідь; зберегти нову версію явно.
4. Запустити **Безпечний прогін** одного героя; вручну запустити нову подію. На фазі попередження прочитати ознаки, обхід і залишок ходів. Перевірити активну фазу, відповідь, повідомлення про припинення та cooldown.
5. Повторити новим прогоном без відповіді: природне завершення знімає тимчасовий ефект. Після дострокової відповіді спочатку закінчити cooldown і підготувати механіку повторно; повтор не дублює подію чи витрату.

Кожну механіку перевірити окремо й записати PASS/FAIL, mapId/mapRevision/runId/runRevision, ресурси/час до та після дії. Стан має зберігатися на сервері. Далі перевірити поєднання.

## Окремі механіки — всі production-сценарії НЕ ВИКОНАНО

| Механіка | Очікувана активація | Відповідь, обхід і завершення |
|---|---|---|
| Обвал / блокування мосту | Тріск/решітка перед перекриттям; під час активності прохід мостом закритий | Реальний нижній обхід доступний. Нижній важіль припиняє подію; після завершення повертається базовий стан проходу. |
| Уламки / смола згори | Небезпека лише під вибраним мостом; відкритий нижній вузол отримує шкоду | Вузол з укриттям захищає від цієї механіки. Відхід/вимкнення джерела діють; інші нижні кімнати незмінні. |
| Підйомний міст | Ланцюги попереджають, механізм перекриває верхній перехід | Спуститися нижнім шляхом або опустити міст нижнім механізмом; перевірити час і звичайні витрати переходів. |
| Ілюзія безпечного маршруту | Хибна підказка позначена як переконання; ознаки обману доступні до пастки | Дослідити ознаки біля початку мосту. Знання героя доповнюються; фактичні ребра/координати не підмінені підказкою. |
| Перехресний вогонь згори | Попередження про стрільців; шкода у відкритих нижніх вузлах під цим мостом | Укриття, обхід або відволікання. Вимкнення джерела припиняє саме пов’язаний обстріл. |
| Засада згори | Ознаки над коридором; під час активності вхід у зону заблокований | Втеча з зони або підйом можливі за правилами карти; приманка знизу припиняє засаду. Немає неминучого замикання. |
| Газ / вода внизу | Шипіння/підйом рівня; шкода наростає за активними кроками | Реальні сходи/драбина/підйомник ведуть нагору. Укриття не захищає від затоплення; нижня подача вимикається. Таймер і шкода не скидаються при reconnect. |
| Бар’єр із генератором унизу | Попередження поля; заблокований вихід мостом | Нижній генератор знімає поле; повторне підготування й cooldown мають правильний стан. Інші мости не змінюються. |

Вороги/смола/газ тут — літературні події, ресурсні наслідки та стани, а не нова FPS-фізика або 3D-спавн. Груповий режим/видимість читача — наступні Т9.6–Т9.7.

## Поєднання, права й відновлення

1. Поєднати блокування мосту та газ, потім додати засаду/обстріл. Незалежні відповіді припиняють власні події; один важіль не скасовує непов’язану небезпеку. Перевірити слабкого героя й довгий перехід, що не вкладається в час попередження.
2. Спроба перекрити останній порятунок або створити несумісні ефекти має відхилятися без зміни ревізії/ресурсів. Недоведена в межах бюджету безпека не є дозволом активувати подію.
3. Повторити той самий запит з ключем повтору: та сама відповідь, без другого знання/ходу. Застаріла ревізія не перезаписує стан.
4. Відновити checkpoint активної небезпеки як новий прогін: та сама версія карти, ресурси, час і фаза. Старий прогін не змінений. Зберегти нову версію карти — старий прогін продовжує свою попередню версію.
5. Перезапустити тестовий сервер/браузер: дострокове припинення й cooldown збережені. Дані PostgreSQL залишаються на налаштованому сховищі; нової міграції Т9.5 не потрібно, основа — Core v37.
6. Гість, сторонній, звичайний читач/редактор і вимкнений акаунт не отримують повну авторську карту через preview/API. Новий `/mechanics/preview` не записує книгу й не створює права.
7. Клавіатура й 390px: бібліотека, поля/кнопки, попередження та повідомлення відповіді доступні, без горизонтального прокручування. Реальний Jev/DeepSeek — окремий прогін Т9.4; платна модель для перевірки механік не потрібна.

## Повтор локальних перевірок

- `npm run test:labyrinth-mechanics` — поведінка, вісім механік, завершення й комбінації; входить до `npm test`.
- На ізольованій локальній PostgreSQL-базі з ім’ям, що закінчується `_t95`, задати `CORE_TEST_DATABASE_URL` і запустити `npx tsx scripts/test-labyrinth-mechanics-api.mts`. Реальну базу/секрети продакшну не використовувати.
- Додати `--browser` у підготовленому Linux-середовищі з Chromium та готовим `dist`: реальні React/API/PostgreSQL, не заглушка UI. Headless-перевірка використовує тестову ідентичність, не Firebase-пароль.
