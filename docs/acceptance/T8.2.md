# Т8.2 — ручне приймання STEAM Teams v2.0

Макети: Stitch 9 `fusion_lab_steam_teams_v2.0_1` і `_2`. Реалізація — Fusion-Lab-Marketplaes, публічні `/teams` і `/teams/:id`, українська й англійська.

1. Оновити Marketplace, виконати `npm ci`, `npm test`, `npm run typecheck`, `npm run build` з власною Firebase конфігурацією. Реальний вхід у production перевіряється окремо.
2. Відкрити каталог в обох мовах: палітра cream/terracotta/sage, вступ, чотири лічильники, пошук, напрями, двоколонкові картки, правила й нижній CTA. Дані мають відповідати опублікованим командам, не числам макета.
3. Перевірити всі п’ять напрямів. Українські значення API лишаються однаковими в обох локалях; підписи англійською перекладені. Фільтр має бути видимим у URL та `aria-pressed`.
4. Знайти команду за назвою, комбінувати пошук із напрямом, перевірити порожній результат і скидання. Після reset поле пошуку має очиститися; після refresh фільтри відновлюються з URL. Лічильники всього каталогу не змінюються від фільтра.
5. «Створити команду» веде до чинної форми `/account/teams/new`, «Мої команди» — до кабінету. Увійти власником, створити команду зі згодою на фото й дочекатися модерації. До схвалення вона не має з’являтися публічно.
6. Запросити двох зареєстрованих учасників. Один приймає, другий чекає. Склад профілю показує лише підтверджених, а кількість зайнятих місць включає очікуване запрошення. Назви й фактичні ролі мають відповідати кабінету. Немає вигаданого ментора, рейтингу чи спеціалізації.
7. Відкрити команду з фото й без фото, перевірити мету/опис і всі п’ять посилань на розділи. Після вибору розділу він доступний, активне посилання позначене. Довгий текст не перекриває sidebar.
8. Власник додає фото й публічний STL/PDF через кабінет. У профілі перевірити назву, розмір і скачування точних байтів файла. Без файлів — зрозумілий порожній стан. Артефакти тут публічні; не завантажувати в них секрети книги.
9. Вакансії, заявки, структурований стек, етапи, командний чат, ревізії, пакетний експорт і Resource ACL мають чесний PLANNED. Не повинно бути фальшивих форм подання/чатів/прогресу чи успішних сповіщень без API.
10. Участь у команді не надає доступу до книги. Окремі ролі й дозволи Collaboration Ontology призначаються в Studio через підтверджену співпрацю. Не заявлено автоматичний міст team roles → book permissions.
11. Перевірити невідому й неопубліковану команду: 404, без приватного складу чи файлів. При недоступному API каталог лишається доступним із порожнім станом.
12. Пройти на телефоні 390px: пошук, reset, картки, навігація розділів і файли. Немає горизонтального переповнення сторінки; широка таблиця може прокручуватись всередині. З клавіатури видно focus; кнопки/посилання мають доступні назви.

## Межі

Локальна хмарна перевірка використовує реальні Next/Nest/PostgreSQL з ізольованими тестовими даними й тестовим Firebase verifier. Це не підтверджує production login, деплой, роботу реальних акаунтів, наскрізне шифрування, age verification або автоматичні виплати. Т8.3 та етап 9 не реалізуються в цьому пункті.
