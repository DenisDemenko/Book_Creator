# Т7.7 — окремий ручний прогін AI Tools

Цей сценарій ще потрібно виконати на production після деплою. Використовуйте тестову книгу / Workspace і погоджений бюджет провайдера. Прогін робить реальні платні генерації; успіхи локальних тестів із stubs не підтверджують ключ чи баланс.

1. Увійдіть власником `tropazemli@gmail.com`, відкрийте тестовий Creative Workspace → AI Tools. У моделі видно тільки availability, без ключів. Переконайтеся, що платформа має активний image/video provider і runtime FFmpeg (після rebuild Railway).
2. Виберіть фахівця `zhdanova9301@gmail.com`, надайте WORK Workspace, VIEW Style Bible, лише одного персонажа та один reference файл. Без окремих дій ШІ запит фахівця відхиляється. Явно надайте спочатку тільки `creative:image:generate`; EDIT і VIDEO залишаються недоступні. Перевірте строк дозволу, CAS і подію надання. Інший письменник / видавець без Workspace доступу не бачить AI Tools цього проєкту.
3. Створіть / активуйте Style Bible. У AI Tools виберіть дозволеного героя й референс, модель / розмір / формат. «Перевірити контекст перед запитом»: активний стиль, тільки дозволені сутності / правила канону; жодних прихованих локацій, біографії, сцен чи нотаток. Спроба використати недозволений ID відхиляється. Ключі й готовий context із клієнта не приймаються.
4. Без checkbox «Підтверджую запит…» кнопка запуску недоступна. Після підтвердження job повертається негайно; сторінку можна оновити, стан залишається. Дочекайтеся COMPLETED, виберіть нову чернетку й відкрийте «Роботи». Перевірте DRAFT, фактичного автора / модель / параметри, job і prompt reference. Немає автоматичних approval / медіаімпорту / CANON.
5. Повтор того самого requestId після втрати відповіді повертає попередній job без нового платного виклику. Друга паралельна генерація іншого requestId відмовляє. Зміна тіла зі старим ID — конфлікт. «Підготувати нову спробу» створює окремий підтверджуваний запит. Ліміти: image quota тарифу, storage quota, 20 image / 5 video прийнятих спроб UTC на добу й один active job. Невдала прийнята спроба також входить у денний ліміт; не витрачайте реальний бюджет для вичерпання ліміту, це покрито автоматичним тестом.
6. Надайте `creative:image:edit`, виберіть поточне власне зображення в «Роботи», поверніться AI Tools і створіть його нову версію за інструкцією / reference. Старий файл незмінний, root / parent / version правильні. Старий parent, чужа робота, FINAL / ARCHIVED не приймаються. Модель без reference editing недоступна для цієї дії.
7. Надайте VIDEO GENERATE / EDIT. Згенеруйте короткий ролик за дозволеним приватним першим / останнім кадром (коли модель підтримує два). Потім виберіть поточне власне відео й «Нова відеоверсія за першим кадром». FFmpeg читає кадр; новий ролик зберігається як наступна DRAFT версія. Це новий ролик за reference, його рух і монтаж треба переглянути вручну.
8. Власник / MANAGE Style Bible може змінити стиль лише завдання через override; VIEW фахівця не може. Перевірте, що активна версія книги й старі approved / CANON assets не змінюються. Під час генерації активуйте іншу версію стилю — пізній результат не додається. Повторна активація того самого стилю не повинна губити результат.
9. Поки job виконується, відкличте дію ШІ / доступ до сутності / reference або вимкніть користувача. Пізня відповідь не створює файл; приватний job endpoint відмовляє після відкликання. FORBIDDEN опублікованого брифу блокує запуск до провайдера, навіть коли чернетка дозволяє ШІ. Скасований / завершений проєкт не генерує.
10. Пройдіть окремий submit / owner approve → явне перенесення в Media Library. У походженні зберігаються job, style version / override, вибрані сутності / reference IDs, provider / model / settings. Клієнт не може переписати цю вихідну декларацію. Канон додається лише окремою дією Т7.6.
11. При помилці ключа / балансу / провайдера — безпечне повідомлення без ключа й сирої відповіді. При storage quota / зміні parent — FAILED, без часткового файла / version / завершеної події. Витрачений provider credit не повертається автоматично.
12. Оновіть сторінку / перезапустіть тестовий сервіс із томом: completed jobs і версії не зникають. Перерваний RUNNING через 20 хв очищується при наступному читанні, автоматичних повторних платних викликів немає. На телефоні 390px перевірте моделі, контекст, checkbox, grants, jobs і вибір чернетки без overflow. При зміні акаунта старий приватний контекст прибирається.

Автоматично: `npm run test:creative-ai`, `npm run test:creative-ai -- --browser`, `npm run test:creative-ai-provider`; ізольований PostgreSQL через `CORE_TEST_DATABASE_URL`; `npm test`, `npm run lint`, `npm run build`.

Відкладені нагадування: Т4.3 та захищений `SECRET_VAULT_KEY_BASE64` Railway. Наступний пункт плану після Т7.7 — Т8.1 (архів Stitch 9 потрібен для точного відтворення).
