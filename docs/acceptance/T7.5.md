# Т7.5 — живий прогін медіатеки з походженням

Після деплою Studio на https://www.fusionlab.in.ua/studio. Потрібні окремі
сесії власника та обраного активного фахівця. Використати тестову книгу й
творчий проєкт, не робочі рукописи. Ключі/паролі в консоль чи звіт не копіювати.
Перевірити persistent DATA_DIR/SQLite volume й зробити штатний backup до
оновлення схеми. Нових міграцій Marketplace немає.

1. **Права.** Надати фахівцю тільки Workspace WORK. Він завантажує роботу,
   але не затверджує й не переносить її у медіатеку автора. Гість, сторонній
   і не-власник із роллю адміністратора не можуть імпортувати результат.
2. **Явне перенесення.** Власник затверджує версію. У «Роботах» вибирає її,
   тип COVER/IMAGE, на основі яких персонажів/локацій/сцен її створено, теги.
   До checkbox «Підтвердити перенесення» кнопка недоступна. Після перенесення
   є saved state і системна подія. Повторити: немає другого файла/події.
3. **Походження.** У медіатеці → «Походження» відкрити результат. Перевірити
   автора-фахівця, початкову дату, книгу й CreativeProject, точний Workspace
   asset/version/parent, хто/коли затвердив і хто переніс. Ліцензія unknown,
   поки власник не вкаже правдиву. CANON не встановлюється.
4. **Приватність.** У сесії фахівця з Workspace-only доступом результат
   Workspace читається, проте файл у медіатеці власника не відкривається без
   окремого media grant. Перенесення не додає grants чи учасників.
5. **Версії.** Завантажити v2 (v1 має бути APPROVED, не FINAL), вимагати змін,
   подати повторно й затвердити. Перенести v2. Обидві версії/байти й історія
   залишаються; галерея показує latest, «Походження» — обидві. Нова версія
   має власну декларацію ШІ. Спроба з застарілою ревізією — конфлікт.
6. **ШІ.** Для ручного файла вибрати «без ШІ», для зовнішньої генерації —
   «використано ШІ», provider/model, відомі generation ID/prompt reference
   і параметри. Це декларація автора файла. Бриф FORBIDDEN приймає тільки
   used=false; DISCLOSE не приймає unknown. Для реальної генерації через
   Studio перевірити провайдера/модель/відомі settings у паспорті; API key
   не має бути в metadata, відповіді чи історії. Платна генерація потребує
   чинного ключа й доступу; локальний тест її не виконує.
7. **Фільтри окремо.** Тип, статус, автор, CreativeProject, ШІ/ручна/невідомо,
   персонаж, локація, сцена, дата від/до, тег. Перевірити кожен самостійно,
   потім комбінацію COVER + без ШІ + тег. Скинути фільтри, показати все.
8. **Паспорт і зв’язки.** Змінити теги/статус REVIEW після підтвердження.
   У двох вкладках змінити один metadata revision: друга отримує конфлікт.
   Походження автора/імпорту/Workspace approval не змінюється. Вибирач сцен
   походження використовує ID рукопису. Окремо через «Прив’язки до книги»
   додати портрет/локацію/сцену; цей старий механізм використовує Core IDs.
9. **Формати.** Окремо MP4/WEBM, MP3/WAV/OGG, PDF, ZIP, GLB: завантажити
   валідний файл у Workspace, затвердити, перенести, завантажити оригінал.
   Байти/MIME збігаються. PDF/ZIP/GLB завантажуються як файли; для аудіо й
   відео є player. Неправильні сигнатури й файл понад 20 МБ відхиляються.
10. **Сховище й квота.** Перевірити додаткову копію під DATA_DIR/media і quota
    власника; успішний повтор не списує повторно. Через штатний redeploy/
    restart перевірити файли, походження, історію й idempotence. Видалити
    тільки тестовий файл: історія й tombstone зберігаються, повторний імпорт
    цього результату повертає 410. Quota refund наразі не автоматичний.
11. **Телефон.** Ширина 390px: форма, checkbox, фільтри, довгі ID й історія
    доступні без горизонтального прокручування. Перевірити на реальному
    телефоні, зокрема відтворення локальних аудіо/відео форматів.

## Локальні автоматичні команди

```bash
npm run test:media-provenance
npm run test:media-provenance -- --browser
# CORE_TEST_DATABASE_URL: лише окрема тестова PostgreSQL-база, ніколи production.
npm run test:creative-workspace
npm run test:media-passport
npm test
npm run lint
npm run build
```

Звіт: акаунт/роль без секретів, URL тестового проєкту, версії/ревізії,
очікуваний і фактичний результат кожного пункту, помилка/скриншот за потреби.
Не прирівнювати локальний тестовий auth до Firebase чи Git push до деплою.
Нагадування: захищений SECRET_VAULT_KEY_BASE64 на Railway, відкладений Т4.3.
