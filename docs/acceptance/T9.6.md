# Т9.6 — приймання цифрового читача

Реалізовано 12.10.2026 у хмарній робочій копії. Production-приймання **НЕ ВИКОНАНО**; коміт/пуш Book_Creator у цьому пункті не запитано.

## Підготовка

Після дозволеного деплою Core має міграціюv38. Автор і два тестові читачі входять власними акаунтами. Потрібні тестова книга, право її перегляду, збережена дворівнева карта з прив'язаними сценами, небезпека з попередженням і далека закрита сцена. Для тесту використовуйте вигадані дані.

Автор: Конструктор структури → Книга-лабіринт → Версія для читачів. Читач: пункт меню **Читач лабіринта** або /studio/projects/ID/labyrinth-reader. Проходження незалежні й сольні.

## Хмарний прогін

Фактично пройшли: проєкція/роль/маршрут12/0, справжні API/PostgreSQL31/0, Chromium19/0; авторська/Core регресія145/0. Повний npm test, типи й build — exit0. Це контрольований хмарний прогін, а не виконання production-сценаріїв таблиці вище.

1. npm run test:labyrinth-reader — проєкція, туман, знання, локальні події, строгі дії та право ролі читача на нове меню.
2. CORE_TEST_DATABASE_URL для окремої localhost бази з суфіксом _t96 → npm run test:labyrinth-reader:api.
3. npm run build; та сама тестова база → npm run test:labyrinth-reader:browser.
4. npm test; npm run lint; npm run build.

Тести відмовляються працювати з production/нелокальною базою. Browser runner використовує /usr/bin/chromium, реальні компоненти, локальний API і CSS поточної збірки. Тестові ідентичності не є справжнім Firebase-входом. Платний Jev/LLM не викликається. Остаточні результати записано у #428.
