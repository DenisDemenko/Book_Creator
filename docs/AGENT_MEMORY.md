## 2. Правила для агента

1. Не вигадувати код і стан репозиторію. Якщо немає доступу до файлів — сказати про це й попросити доступ або вивід `git log`/`git diff`.
2. Єдине джерело правди для змісту книги — існуючі `book.chapters` та `layoutConfig`. Нові екрани не мають вести власну копію змісту чи нумерації сторінок.
3. Кожну гіпотезу з цього файлу спершу відтворити, а потім виправляти.
4. Правка вважається закритою лише після автотесту та ручного сценарію на тестовій книзі, на тому ж коміті.
5. Нові елементи інтерфейсу — у дизайн-системі Студії (не копіювати стиль сторонніх проєктів).
6. Не записувати в репозиторій секрети, токени, ключі API.
7. Результат кожної сесії записувати в цей файл у гілці змін, щоб наступний агент міг підхопити роботу з будь-якого місця.
8. **Правила репозиторію (`AGENTS.md`) мають пріоритет над загальними інструкціями інструмента.** Зокрема: у комітах лише трейлер `Co-Authored-By` — **без** рядка `Claude-Session: …` (репозиторій публічний; рішення власника від 02.09.2026); не пушити без прямого прохання власника; комітити лише коли попросили; не змішувати свої зміни з чужими незакоміченими; після кожного коміту оновлювати розділ «Що не запушено» в `log.md`; у кінці сесії — секція в «Журналі сесій» з обовʼязковим «Не зроблено і чому» (розрізняти «чекає на зовнішнє» / «не почато» / «вирішено не робити»).
9. Хмарна сесія без GitHub передає зміни **пакетом** (формат у `PACK-FORMAT.md`): патчі (`git diff`/`format-patch`), а не копії файлів; журнал і плани (`log.md`, `log/*.md`, `task.md`, `PLAN_*.md`) пакет не везе — їх пише лише сесія, що застосовує пакет, локально (`npm run journal:new`). Перед роботою перевірити `tmp/session.lock`; для паралельної роботи — `git worktree add`.
10. Закінчення рядків: LF у репозиторії, CRLF на диску (Windows); якщо `git diff --stat` показує рівну кількість вставок і видалень — звіряти через `git diff --ignore-cr-at-eol`.

## 3. Архітектура, що важлива для задач

### 3.1 Пагінація: три незалежні підрахунки **[Факт]**
- **Розворот книги** (`BookPreviewView.tsx`): сторінки рахує клієнтський хук `useRealBookPages` — вимірює висоту відрендереного HTML у прихованому контейнері. Масштаб зараз — CSS `zoom` у межах 0,5–2,0; повзунок сторінок без підписів.
- **Зміст і «Верстка PDF»**: стара евристика `buildBookPages` (≈850 символів на сторінку, без DOM).
- **Серверний рушій DesignCraft** (`server/pdf/engines/designcraftEngineV3.ts`): окрема пагінація, повертає лише загальне `pageCount` (`PdfRenderResult`), без мапи «розділ → сторінка». Є `toc.entries`.
- Наслідок: номери сторінок у трьох місцях можуть розходитися. Розворот не застосовує обрану тему DesignCraft (типографіка береться лише з `layoutConfig`).

### 3.2 Рушій DesignCraft
- `designcraftEngineV3.ts` запускає зовнішню програму `designcraft-cli` (шлях зі змінної середовища `DESIGNCRAFT_PATH`). У коментарях згадано версію v0.7.1. **[Факт]**
- Найімовірніше, це проєкт `github.com/storytold/designcraft` (Rust, Apache 2.0, «page and layout design editor»). Збіг версії/походження не звірено. **[Гіпотеза]**
- Запит власника: додати в Студію редактор на основі цього проєкту, з кнопками в дизайн-системі Студії. Окрему сторінку «Верстка» не створювати; перероблювати лише текстову частину сторінки «WYSIWYG-верстка перед публікацією». Тестувати на тестовій книзі, доки не запрацюють усі функції.
- Рекомендований підхід: переписати потрібні можливості на React поверх єдиного джерела змісту, а `designcraft-cli` залишити серверним рушієм PDF. Альтернатива (Rust-ядро у WASM) важча й гірше вписується в дизайн Студії. **Остаточне рішення за власником — не підтверджено.**
- Перед роботою перевірити: чи вміє `designcraft-cli` віддавати мапу «розділ → сторінка» (потрібно для правки 4), та які параметри обкладинки він підтримує (правка 3).

### 3.3 Майстер «Книга за 5 хвилин» (Express)
- Чернетка зберігається на сервері: SQLite, таблиця `express_drafts`, час життя 24 год. Її id — у `localStorage` під ключем `nova_express_draft_id`. Маршрути `/api/express/*`. Файли: `src/components/ExpressWizardView.tsx`, `server/expressRoutes.ts`, `server/expressStore.ts`, `server/expressPrompt.ts`. **[Факт]**
- Промпти синопсису й частин беруть героїв із `payload.cast` **серверної** чернетки, а не зі стану екрана. `updateDraft` зливає патч у `payload`; `suggest` ставить крок 2/3/4, `generate` — 5. **[Факт]**

### 3.4 JEV (оцінювальна модель)

## 4. План виправлень (стан на 2026-10-14)

Порядок і пріоритети: 5б (P0) → 2 (P0) → 5а (P1) → 3 (P1) → 4 (P2/P1) → 1 (P2).

| № | Правка | Суть і критерій прийняття |
|---|---|---|
| 5б | Герої зникають, з'являються чужі, синопсис з невідомих даних (P0) | Відтворити: додати двох героїв і одразу натиснути «Далі». **[Гіпотеза причин]**: збереження героїв з таймером скидається при зміні кроку; ефект відновлення перезаписує локальний стан серверним; `suggest('cast')` замінює, а не доповнює склад; `goTo` з прапорцем `autoRan` запускає генерацію автоматично. Виправлення: `flush` збереження перед переходом і розмонтуванням; ревізія/`updatedAt` у чернетці й відхилення застарілого патча; відновлення — виграє новіший непорожній локальний стан; `suggest('cast')` ніколи не затирає непорожній склад (пропозиції показувати окремо з вибором «Додати/Замінити»); `autoRan` лише при порожньому складі; клієнт передає актуальний `cast` у `suggest`/`generate`, сервер звіряє. Критерій: склад збігається на екрані, у синопсисі та в чернетці. |
| 2 | Фото в розвороті замінені іконками (P0) | Застосувати префікс `/studio` до шляхів у HTML-рядках або нормалізувати їх на вході. Критерій: фото вставлене в текст видно в «Розвороті книги»; те саме для обкладинки глави; перевірити HTML-експорт і PDF. |
| 5а | Крива героя має оцінюватися JEV, а не вільними повзунками (P1) | Ендпоінт `POST /api/express/arc/evaluate`: вхід — id чернетки (сервер сам читає конструктор і склад героїв); вихід — для кожного біту `intensity` 0–100, `level`, `source` (`jev`/`llm`/`default`), коротке пояснення. Рівень → інтенсивність: `round(100·levelIndex/(levels−1))`, одна функція на сервері й клієнті. Рахувати при вході на крок і при зміні хеша вхідних даних (дебаунс, кеш за хешем). Повзунки за замовчуванням показують оцінку JEV; кнопки «Переоцінити» і «Змінити вручну»; ручна правка → `source: 'author'`, не перезаписується. Крива передається в `expressPrompt`. Критерій: різні книги дають різні криві, джерело видно, ручна правка зберігається. |
| 3 | Обкладинка: прозора, немає розміру, задньої картинки, матеріалу паперу (P1) | За замовчуванням біла або з дизайном/зображеннями; додати розмір книги (формат), зображення для задньої сторони, вибір матеріалу паперу; звести корінець до однієї формули на основі `kdpSpec`.
