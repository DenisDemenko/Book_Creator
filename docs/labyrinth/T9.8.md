# Т9.8 — завершене проходження → нова книга

Реалізовано 13.10.2026. Автор у конструкторі карти відкриває «Проходження → нова книга», вибирає завершений одиночний або груповий маршрут і збирає приватну чернетку. Факти, сцени, погоджені внески та фінал мають окремі джерела. Після перевірки автор створює нову серверну книгу й відкриває її у чинному редакторі.

## Джерела та причинність

- Використовується immutable версія карти й текст сцен із reader edition. Незбережена/нова карта не переписує історичний маршрут.
- Кожен фрагмент має run ID, ревізію журналу, map/book revision, час історії, героя/місце, scene/contribution ID та SHA-256 оригіналу.
- Фактичні переходи звіряються з графом і станом героя. Ресурси, видимі зміни механізмів, попередження/активація/завершення небезпеки походять зі станів журналу. Сплив часу не оголошується перемогою.
- Group restore відсіює покинуту гілку та її внески. Solo fork додає передісторію точного checkpoint; глибина обмежена 32, журнал — 1500 записами.
- Минулі фізичні дії героя, який залишив групу, зберігаються. Його фінальний стан не перетворюється на невиконаний вихід. Усі активні герої мають реально завершити маршрут.
- Новий рукопис не змінює базову книгу, карту або проходження.

## Приватність і редакція

Авторські endpoints доступні власнику книги/адміністратору з повторною перевіркою актуального акаунта та доступу. Усі відповіді `no-store`.

У матеріал не копіюються чати, приватні діалоги, пам'ять/знання/плани/страхи героїв, account IDs/email учасників або незвідані сцени. Внесок включається лише за чинною окремою згодою, candidate/terms та доступом учасника; текст лишається дослівним. Покинута гілка й відкликані/недоступні внески виключаються.

ШІ запускається окремим підтвердженим запитом через чинний платформний text adapter та модель модуля `coreAi2Analysis`. Передаються тільки факти/відкриті сцени й час; тексти внесків не надсилаються. Відповідь повинна містити кожен відомий ID рівно один раз у правильному порядку. Нові джерела, пропуски, перестановки, дублікати та додаткові поля відхиляються.

Схема перевіряє джерела та структуру; зміст літературної пропозиції перевіряє людина. Оригінальні факти й фінал не переписуються моделлю. Автор може редагувати пропозицію, повернути оригінал або відхилити збірку. У новій книзі зберігаються походження, AI-ознаки й `[AI-DRAFT]` для прийнятої пропозиції ШІ.

Ліміти: 2500 фрагментів/2 МБ джерел, 40 000 символів JSON-входу ШІ, 16 000 символів на редакцію фрагмента, 2 МБ raw AI output; тайм-аут 60 с (провайдер 55 с). При перевищенні AI-ліміту доступна ручна збірка. Ключі/URL/model parameters не приймаються від клієнта.

## Транзакції та відновлення

Core v40 зберігає `labyrinth_story_drafts` і `labyrinth_story_requests`. CAS захищає редакцію й прийняття, серверні receipts — повтори. Одна генерація на чернетку; очікування моделі відбувається без блокування run, щоб згоду можна було відкликати. Пізня відповідь після зміни джерел/прав/редакції не записується. Покинута генерація після 2 хвилин не повторюється автоматично; нова спроба потребує нового підтвердженого запиту.

Прийняття вимагає явних `confirm` і `causalityReviewed`. Нова книга має ID `LB-STORY-<draftId>`, початкового власника, status `draft`, власні глави/розділи, метадані походження та звичайне сховище SQLite/JSON. Перевірка автора й внесків виконується всередині черги `saveBook` безпосередньо перед записом. Після збою між записом книги й Core commit повтор повертає ту саму книгу; `reviewHash` не дозволяє підмінити іншу редакцію.

Остаточне співавторство, ліцензія, редакторські погодження, експорт видання й публікація — Т9.9. `legalAuthorship=false`, `publicationReady=false`; автоматичної публікації або нових grants немає.

## API

Префікс: `/api/core/projects/:projectId/labyrinth`.

| Метод | Шлях | Дія |
|---|---|---|
| GET | `/maps/:mapId/story-drafts` | Завершені маршрути й метадані збірок |
| POST | `/runs/:runId/story-drafts` | Зібрати оригінали та джерела |
| GET | `/story-drafts/:draftId` | Чинна приватна чернетка |
| POST | `/story-drafts/:draftId/edit` | Ручна літературна редакція |
| POST | `/story-drafts/:draftId/rewrite` | Окрема пропозиція ШІ |
| POST | `/story-drafts/:draftId/reject` | Відхилити; явна нова збірка може відновити новою ревізією |
| POST | `/story-drafts/:draftId/accept` | Прийняти в нову книгу |
| GET | `/story-drafts/:draftId/book` | Відкрити створений рукопис |

Перевірки: модель12/0, PostgreSQL/API+SQLite29/0, PostgreSQL/API+JSON29/0, Chromium8/0. Типи, npm test та production build перевіряються окремо. [Ручне приймання](../acceptance/T9.8.md) ще відкрите для активного deployment, Firebase, реальних облікових записів і справжньої моделі.
