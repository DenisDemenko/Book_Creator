## Підготовка версії

- Джерело — прийнятий Т9.8 рукопис у серверному реєстрі. Клієнтський
  прапорець походження не є доказом. Перед створенням версії книгу
  потрібно зберегти; незлиті редакторські пропозиції блокують підготовку.
- Титульний склад: письменник, співавтор, редактор, ілюстратор, видавець
  або учасник подяк. Публічне ім’я може бути псевдонімом. До складу можна
  додавати чинних учасників джерела або спільної роботи з книгою.
- Автори включених літературних внесків і прийнятих редакторських правок
  обов’язково отримують особисте погодження. Автоматичне присвоєння
  співавторства після входу або ходу відсутнє.
- Внесок із відкликаною згодою можна явно вилучити: із нової версії
  забирається його текст, а не тільки ім’я. Оригінальна приватна книга
  та її історія зберігаються.
- Умови: усі права захищені, CC BY 4.0 або власний текст ліцензії;
  безоплатне розповсюдження чи продаж. Для продажу частки задані явно
  й у сумі становлять 100%. Вони зберігаються як погоджені умови версії;
  автоматичні виплати цей модуль не виконує.
- Передмова «Як створено цю історію», подяки та обкладинка PNG/JPEG
  до 2 МБ входять до незмінної версії. Зовнішні URL обкладинок не приймаються.

## Особисте погодження та редакція

Учасник відкриває версію в кабінеті читача джерела → **«Видання з моєю
участю»**. Він бачить повний текст для погодження, власні початкові
внески та їхню поточну редакцію, публічний склад, ліцензію й частки.
Приватні чати, знання героїв і дані акаунтів у видання не переходять.

Погодження потребує п’яти окремих підтверджень: прочитаний текст,
ім’я/роль, ліцензія, публікація повного тексту та умови розповсюдження
з часткою. Відмова і відкликання є окремими рішеннями. Автор не може
погодити участь іншої людини. Рішення прив’язане до snapshot hash
конкретної версії та власної ревізії рішення.

Редагування використовує чинні запрошення й grants, спільний редактор,
Change Proposals та історію серверних ревізій. Запрошення до погодження
саме по собі не відкриває редагування. Пропозицію співавтора схвалює
власник; злитий внесок зберігає автора. Обговорення видання є приватним
для його учасників і не додається до публічного тексту.

Зміна рукопису, обкладинки, імен, ролей, складу, ліцензії або часток
потребує нової версії й нових рішень. Попередня опублікована версія
залишається незмінною; її видача продовжує перевіряти чинні права та згоди.

## Експорт і публікація

Фінальний експорт доступний після всіх погоджень: PDF, DOCX, EPUB,
HTML, Markdown та JSON. PDF використовує чинний серверний renderer;
DOCX/EPUB — чинні експортери Студії з дозволеним сервером знімком книги.
Титул і метадані містять погодженого письменника та співавторів;
передмова й титульний склад також містять решту ролей і ліцензію.
HTML/JSON зберігають вибрану ілюстрацію обкладинки. PDF/DOCX/EPUB
використовують чинну текстову верстку Студії; друкарський макет обкладинки
готується через її існуючі інструменти й приймається окремо.

Цифрове HTML-видання дає читання розділів завершеного маршруту, карту
відвіданих місць, маркер поточного розділу й вибір нижнього/верхнього
рівня. Це видання пройденої історії. Нове інтерактивне проходження
здійснюється в чинному читачі Т9.6–Т9.7.

Публікація потребує окремого підтвердження, погодженої ролі письменника
або видавця та чинного дозволу `canPublish`. Сервер повторно перевіряє
всіх учасників, згоди, незлиті пропозиції та ревізію рукопису.
Повтор із тим самим ключем повертає ту саму версію. Відкликання після
публікації закриває наступну публічну видачу й експорт, зберігаючи аудит.
Вже завантажені учасниками файли залишаються на їхніх пристроях.

Старі PDF/Etsy publish API перевіряють серверне походження
`LB-STORY-…` і погоджені `LAB-EDITION-…`; видалення клієнтського прапорця
не обходить погоджень. Для продажу потрібні погоджені комерційні умови.

## Сховище та API

Core v41: `labyrinth_book_editions`, `labyrinth_edition_agreements`,
`labyrinth_edition_events`, `labyrinth_edition_requests`. Рукопис продовжує
використовувати SQLite або JSON. Черга запису книги утримує знімок під
час створення, погодження та публікації; зміна ревізії відхиляє стару дію.
Ключ команди, CAS та журнал зберігаються в PostgreSQL.

Приватний префікс: `/api/core/projects/:bookId/labyrinth-editions`:

| Метод | Шлях | Призначення |
|---|---|---|
| GET | `/context` | Авторські налаштування, внески, склад і версії |
| POST | `/` | Нова незмінна версія поточного рукопису |
| GET | `/:id` | Дозволений перегляд для учасника |
| POST | `/:id/decision` | Особисте погодження, відмова чи відкликання |
| POST | `/:id/comments` | Обговорення версії |
| POST | `/:id/publish` | Окрема явна публікація |
| GET | `/:id/export/:format` | `pdf`, `md`, `html`, `json`, `book` |

Inbox: `/api/core/projects/:sourceId/labyrinth/reader/book-editions`.
Публічне читання: `/api/labyrinth-editions/:id/read`; метадані —
`/api/labyrinth-editions/:id/metadata`. На production префікс `/studio`.
Приватні відповіді та видача видань мають `Cache-Control: no-store`.
HTML використовує nonce CSP, екранування і `textContent`.

## Перевірки

Локальні синтетичні дані, без платних провайдерів і production-записів:
модель **10/0**, PostgreSQL + SQLite API **33/0**, PostgreSQL + JSON
API **30/0**, Chromium **12/0**. Реальні файли PDF/DOCX/EPUB перевірено,
включно з іменами у PDF та XML/OPF метаданих. Редакторський прогін
здійснює справжні source/Change Proposal/merge/history запити.

Команди: `npm run test:labyrinth-edition`,
`npm run test:labyrinth-edition:api`,
`npm run test:labyrinth-edition:api -- --json`,
`npm run test:labyrinth-edition:browser`. Для API потрібна окрема локальна
`CORE_TEST_DATABASE_URL` із назвою бази, що закінчується `_t99`;
production URL тест відхиляє. Browser потребує Chromium і зібраних CSS.
Повне приймання двох різних видань належить Т9.10.
