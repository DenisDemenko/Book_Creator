# Т4.2: продуктивність і контроль витрат

Профіль і знімок героя кешуються в пам’яті процесу. Ключ знімка включає
проєкт, героя, ревізію ядра книги, сцену (межу story time), главу, прогін,
ситуацію, дозволені дії, картку Студії та бюджет. Профіль кешується окремо:
новий прогін незмінної сцени повторно використовує профіль.

Перед поверненням кешу повторно перевіряються SHA-256 відбитки всіх прочитаних
джерел репозиторію. Це також ловить правки канону, пам’яті, зв’язків і доказів,
що не збільшують ревізію книги. Кеш скорочує повторне складання профілю та
графа; читання залежностей бази залишається. Немає твердження про виміряне
прискорення на великих продакшн-книгах. Межі: 60 секунд, 128 записів / 8 MiB
на репозиторій, до 1 MiB на запис. Результати копіюються, одночасні однакові
побудови об’єднуються. Авторизація виконується маршрутами й tools до читання;
ключ кешу не надає доступ. Secret Vault не допускається як джерело кешу.

Підготовка 2–3 героїв виконується паралельно. Рішення, голос і запис ходу
залишаються послідовними. Три рівні Jev зберігають свої чинні ключі:
стратегічний — значущі зміни; сценічний — умови сцени й батьківське рішення;
тактичний — знімок і хід. Кешовані рішення знову не викликають провайдера.

Синхронізація `core_sync` уже працює інкрементально: теги й позначки перегляду
перераховуються на змінених / видалених доказах. Її фонова PostgreSQL-черга
зберігає задачі, оренду, повтори, скасування й бюджети проєкту.
Для інтерактивних step/draft додано обмежену FIFO-чергу: 16 операцій на
проєкт, 128 на процес. Операції різних проєктів незалежні; після помилки
черга продовжується. Ця інтерактивна черга не переживає перезапуск процесу:
клієнт оновлює прогін і повторює запит, а збережені CAS/idempotency та busy
захищають від дублювання й конкурентних інстансів. Це не спільна розподілена
черга та не гарантія глобального ліміту провайдерів між інстансами.

Кожна інтерактивна AI-операція має консервативний бюджет 96 000 токенів:
UTF-8 байти входу + резерв виходу до виклику Jev / fallback / voice / writer /
приватного вибору. Це верхня оцінка, не точний tokenizer. Вихід LLM обмежений
1800 токенами, таймаут — 30 секунд. Резерв не повертається після помилки.
Вартість і фактичні токени беруться зі штатної AI-телеметрії; токени Jev
додаються з його відповіді. Вартість Jev без тарифу не оцінюється як відома.

`POST .../simulations/:id/draft-stream` повертає NDJSON `fragment` і
`complete`. Потік починається після генерації та перевірки всього JSON:
це передача перевірених фрагментів, не сирих токенів провайдера. Перевірені
фрагменти вже збережено в прогоні; розрив потоку не втрачає їх. Права
перевіряються перед генерацією й перед відповіддю. Рукопис змінюється лише
після окремого затвердження через гілку з continuity/causality перевірками.

Адмінка «Якість персонажів» показує `/api/admin/quality/performance`:
побудови / попадання кешів, Jev / fallback, відхилені рішення, виявлені
continuity / causality попередження, токени, вартість, помилки AI, час черги,
середню затримку й p95 останніх 512 операцій. Це агрегати поточного процесу,
скидаються після перезапуску, без project/character ID, промптів, тексту,
секретів і повідомлень винятків. Повторна перевірка проблеми рахується
повторно; це число спостережень, не унікальних проблем. Endpoint лише для
адміністратора, `Cache-Control: no-store`.

## Повторювані прогони

- `npm run test:performance -- --browser`: кеші, зміна доказу/канону без
  ревізії, часові межі, новий прогін, копіювання, single flight, Vault deny,
  бюджет, FIFO, переповнення, відновлення після помилки, приватність,
  адмін API і справжній Chromium.
- `npm run test:magic-scene -- --browser`: послідовні ходи, скасування,
  ізоляція, валідація потоку, відмова читачеві, незмінний рукопис до автора,
  браузерний шлях через потокову чернетку й затвердження.
- `CORE_TEST_DATABASE_URL=...` додає ті самі перевірки на окремій тестовій
  PostgreSQL. Реальні платні AI та продакшн цими прогонами не перевіряються.
- `npm run test:jev-levels`, `npm run test:living-characters`,
  `npm run test:secret-vault -- --browser`, `npm test`, `npm run lint`,
  `npm run build` — регресії та загальні перевірки.

Перед продакшн-прогоном нагадати власнику: налаштувати захищену змінну
`SECRET_VAULT_KEY_BASE64` на Railway; значення не передавати в чат чи Git.
Користувач попросив відкласти це нагадування до наступної перевірки продакшну.
