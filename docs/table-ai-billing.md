# AI-візуалізація столу та спільні AI-бали Студії

Унизу `/table-builder` є генерація зображення OpenAI за поточними параметрами й ескізом стільниці. Сервер перевіряє композицію через наявний розрахунок. Результат можна завантажити; це орієнтовна візуалізація, не виробниче креслення. Зміна параметрів приховує старе зображення та відкидає застарілу відповідь.

## Правила оплати

- Вхід обов’язковий. Зареєстрованому користувачу без активної платної підписки — **5 успішних генерацій загалом**, без щоденного чи щомісячного поновлення.
- Підписники витрачають **спільні AI-бали Студії книг**, без окремого ліміту 5 на день. Тариф, модель і баланс беруться зі Студії для кожного запиту. Використовується той самий прямий запис **GPT Image (OpenAI), 1K** з каталогу адмінпанелі Студії; ціна не копіюється в маркетплейс. Реальна модель у виклику OpenAI також береться з цього запису, щоб тариф відповідав обраному рушію.
- Особа зіставляється лише за перевіреним Firebase UID, не за email. Відсутній акаунт Студії означає безкоштовний режим; недоступна Студія чи її БД не означає безкоштовний режим і блокує запуск.
- Студія перевіряє активність і строк підписки. Після її завершення знову діє залишок одноразових 5, а не нові 5. Рахунок безкоштовних генерацій прив’язаний до Firebase UID.
- Бали резервуються до OpenAI, списуються після успіху; помилка повертає резерв. Помилка провайдера також повертає безкоштовний слот. Атомарні операції не дозволяють паралельним запитам витратити останні бали/слоти двічі.
- Захисний ліміт сайту — 100 спроб на добу UTC (не тарифний ліміт користувача). Помилки провайдера витрачають цей захисний ліміт.

Маркетплейс зберігає намір списання/повернення в `TableAiBillingJob`; кожні 30 секунд повторює незавершені ідемпотентні операції. Незавершені резерви після збою процесу повертаються через 10 хвилин. Успішний виклик із невідомим результатом списання лишається зарезервованим до підтвердження, а не повертається помилково. Повторів платного OpenAI-запиту немає. Зображення не додається до замовлення і не зберігається на сервері, тому перезавантаження сторінки після успіху вимагає нової генерації.

## Налаштування й установлення

1. Спочатку встановити суміжний патч `Book_Creator/server/tableAiBilling.ts` і реєстрацію в `server.ts`. Він використовує чинний SQLite-гаманець і налаштування цін Студії, без окремої БД. Маршрути `/api/table-ai/billing/{access,reserve,settle,release}` доступні лише серверу з правильним `x-bridge-key`, не браузеру. Секрет порівнюється з наявним зашифрованим ключем мосту в адмінпанелі Студії.
2. На API маркетплейсу налаштувати `STUDIO_API_URL` (або `NOVA_ORIGIN`) — кореневий HTTPS URL сервера Студії, без `/api`; `BRIDGE_API_KEY` — той самий ключ, що вже використовується мостом Студії. Редиректи заборонені. Секрети не додавати у frontend env/git/логи.
3. Виконати звичайні `npm ci`, `prisma generate`, `prisma migrate deploy`, збірки API/web. Міграція `20261102150000_table_ai` ще в незлитому PR: тепер вона містить також outbox `TableAiBillingJob`. Якщо її вже застосували в тестовій БД попереднього патча, потрібна окрема додаткова міграція, а не зміна історії живої БД.
4. Зберегти стабільний `PAYOUT_DATA_KEY` для наявного AES-256-GCM helper (32 байти: 64 hex або base64). Не змінювати цей ключ шифрування: він використовується також наявними реквізитами.
5. У `/admin/slabs` → **Калькулятор витрат → AI-візуалізація · OpenAI** ввести API-ключ і ввімкнути функцію. Порожнє поле зберігає попередній ключ; видалення вимикає генерацію. GET повертає лише enabled/configured. Доступ лише admin.
6. Reverse proxy для `POST /tables/ai-image`: таймаут щонайменше 180 секунд. OpenAI-запит — до 150 секунд. Перед production перевірити на staging реальний Firebase-вхід, обидва режими, ціни, останні бали, завантаження PNG та відновлення білінгу після перезапуску.

## Перевірки

`node scripts/test-table-ai.mjs` — 22 перевірки маркетплейсу (сервіс/UI, гаманець Студії підставлено, транзакції PostgreSQL моделюються). Суміжний `node scripts/test-tableAiBilling.mjs` — 11 перевірок Студії з реальним SQLite/CreditWallet, підставленими підписками/цінами/авторизацією. Node 24, без платних API-викликів. Синтаксис JS та `git diff --check` перевірені.

Повну збірку/перевірку типів, реальну PostgreSQL, браузерний Firebase та справжні генерації не перевірено: у середовищі часткові вихідні файли без залежностей, shell-доступ до npm/GitHub недоступний. Вихідні файли й публікація — через GitHub connector. Живі баланси, підписки, API-ключі, міграції та production не змінювалися.
