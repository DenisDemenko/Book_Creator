# AI-візуалізація столу та спільні AI-бали Студії

Унизу `/table-builder` є генерація зображення OpenAI за поточними параметрами й ескізом стільниці. Сервер перевіряє композицію через наявний розрахунок. Результат можна завантажити; це орієнтовна візуалізація, не виробниче креслення. Зміна параметрів приховує старе зображення та відкидає застарілу відповідь.

## Правила оплати

- Вхід обов’язковий. Зареєстрованому користувачу без активної платної підписки — **5 успішних генерацій загалом**, без щоденного чи щомісячного поновлення.
- Підписники витрачають **спільні AI-бали Студії книг**, без окремого ліміту 5 на день. Тариф, модель і баланс беруться зі Студії для кожного запиту. Використовується той самий прямий запис **GPT Image (OpenAI), 1K** з каталогу адмінпанелі Студії; ціна не копіюється в маркетплейс. Реальна модель у виклику OpenAI також береться з цього запису, щоб тариф відповідав обраному рушію.
- Особа зіставляється лише за перевіреним Firebase UID, не за email. Відсутній акаунт Студії означає безкоштовний режим; недоступна Студія чи її БД не означає безкоштовний режим і блокує запуск.
- Студія перевіряє активність і строк підписки. Після її завершення знову діє залишок одноразових 5, а не нові 5. Рахунок безкоштовних генерацій прив’язаний до Firebase UID.
- Бали резервуються до OpenAI, списуються після успіху; помилка повертає резерв. Помилка провайдера також повертає безкоштовний слот. Атомарні операції не дозволяють паралельним запитам витратити останні бали/слоти двічі.
- Захисний ліміт сайту — 100 спроб на добу UTC (не тарифний ліміт користувача). Помилки провайдера витрачають цей захисний ліміт.

Маркетплейс зберігає намір списання/повернення в `TableAiBillingJob`; кожні 30 секунд повторює незавершені ідемпотентні операції. Незавершені резерви після збою процесу повертаються через 10 хвилин. Успішний виклик із невідомим результатом списання лишається зарезервованим до підтвердження, а не повертається помилково. Повторів платного OpenAI-запиту немає. Кожне успішне зображення зберігається у приватну чергу модерації маркетплейсу. Адміністратор може схвалити його для першого слайдшоу; без схвалення публічний доступ відсутній. Деталі: docs/table-ai-gallery.md.

## API-ключ: виключно адмінпанель Студії книг

Єдине джерело — наявний розділ **«Ключі API» → OpenAI/GPT** у Студії книг. Адміністратор вводить ключ там, він шифрується чинним механізмом Студії (`userApiKeyCrypto.ts`). Сервер генерації читає лише `platformKeyFor('gpt')`: це ключ активного адміністратора. Власні ключі звичайних користувачів, `OPENAI_API_KEY` та будь-які значення з браузера/маркетплейсу не використовуються для конструктора. Якщо ключа в панелі немає або він не розшифровується — генерація відхиляється.

Запит OpenAI виконує **сервер Студії**, маркетплейс отримує тільки зображення. Ключ не повертається API-відповіддю, не передається мостом і не зберігається в PostgreSQL маркетплейсу. Поле ключа, маршрути ai-settings і модель TableAiSettings з попереднього незлитого патча прибрано. На маркетплейсі залишається лише службовий BRIDGE_API_KEY для авторизації серверного мосту; це інший секрет, не ключ OpenAI.

## Установлення

1. Встановити суміжний PR Студії: `server/tableAiBilling.ts` та `server/tableAiGeneration.ts`. Чинний маршрут `/api/table-ai/billing/:action` має дії access/reserve/generate/settle/release, захищені x-bridge-key. Generate звіряє модель з каталогом та резерв підписника; викликає OpenAI Images Edits з admin GPT key, без fallback.
2. На API маркетплейсу: `STUDIO_API_URL` або `NOVA_ORIGIN` — кореневий HTTPS URL Студії без `/api`; чинний `BRIDGE_API_KEY` — той самий ключ, що в налаштуваннях мосту Студії. Ключ OpenAI на маркетплейсі не потрібен і не приймається.
3. Звичайні `npm ci`, `prisma generate`, `prisma migrate deploy`, збірки API/web. Міграція `20261102150000_table_ai` ще в незлитому PR: тепер містить тільки лічильники та outbox, без сховища ключа. Якщо її попередній варіант вже застосували в тестовій БД, потрібна окрема міграція; не переписувати застосовану історію живої БД.
4. У Студії адміністратор додає OpenAI/GPT через наявну панель «Ключі API». Потрібні наявні налаштування шифрування Студії. Видалення цього ключа робить генерацію недоступною. Інші інструменти Студії не змінюються цим патчем.
5. Reverse proxy для Marketplace `/tables/ai-image` і Studio `/api/table-ai/billing/generate`: таймаут щонайменше 180 секунд. Запит OpenAI у Студії — до 150 секунд. Перед production — staging з реальними Firebase/PostgreSQL, обома режимами, останніми балами, завантаженням PNG та відновленням білінгу після перезапуску.

## Перевірки

`node scripts/test-table-ai.mjs` — 21 перевірка маркетплейсу (сервіс/UI, Studio підставлено, транзакції PostgreSQL моделюються). `node scripts/test-tableAiBilling.mjs` у Студії — 22 перевірки, включно з реальним SQLite/CreditWallet, адміністраторським джерелом ключа, відмовою env/user fallback, санітизацією помилок та відсутністю ключа у відповідях. Node 24, без платних API-викликів. Синтаксис JS та git diff --check перевірені.

Повну збірку/перевірку типів, реальну PostgreSQL, браузерний Firebase та справжні генерації не перевірено: у середовищі часткові вихідні файли без залежностей, shell-доступ до npm/GitHub недоступний. Вихідні файли й публікація — через GitHub connector. Живі баланси, підписки, API-ключі, міграції та production не змінювалися.


## Модерація фото

Додатковий патч створює TableAiPhoto і міграцію `20261102160000_table_ai_gallery`. `/admin/slabs` → **Модерація AI-фото**: усі автори, фільтри pending/approved/rejected, приватні прев’ю, вибір кількох фото, назви/підписи та зняття схвалення. Зберігаються тільки зображення від довіреного генератора, не з браузерного POST. Публічне слайдшоу отримує тільки схвалені фото, без даних авторів. PNG-файли лежать у чинному StorageService: потрібен постійний STORAGE_DIR і резервне копіювання разом із PostgreSQL. Старі результати, які не були збережені попередньою версією, автоматично відновити неможливо.

Перевірки модерації: `node scripts/test-table-ai-gallery.mjs`; регресія генерації — `node scripts/test-table-ai.mjs`. Повна збірка/Prisma/Firebase та справжній браузер не перевірені в цьому середовищі.

## Інтер’єр і до 10 референсів

Під параметрами AI-візуалізації — 14 варіантів: студійне фото/кімната з фото, сучасний, скандинавський, мінімалізм, лофт, індустріальний, класичний, неокласика, джапанді, вабі-сабі, бохо, кантрі, середземноморський, ар-деко. Фото можна додавати кількома виборами до загальної кількості 10, переглядати й видаляти. JPG/PNG/WEBP до 20 МБ на вихідний файл; браузер стискає в JPEG до 250000 символів data URI на фото. Перше фото задає основну кімнату, решта — додаткові ракурси/світло/деталі. Вибраний стиль застосовується до оформлення, архітектура завантаженої кімнати зберігається в інструкції генерації. Без кімнат генерується вибраний стиль. AI-візуалізація лишається орієнтовною, не гарантує точних фізичних пропорцій.

Ескіз стільниці йде першим `image[]`, після нього до 10 окремих JPEG-референсів. Немає колажу чи втрати дев’яти з десяти фото. API та Studio відхиляють більше 10, завеликі значення й некоректні формати до виклику провайдера. Тільки `/tables/ai-image` має JSON body limit 4mb; решта маршрутів зберігають 1mb. Перевірити цей розмір також на reverse proxy. Studio вже приймає 40mb JSON.

Фото кімнат тримаються у пам’яті поточної вкладки та передаються в Studio/OpenAI для запиту. Вони не записуються до draft/sessionStorage, PostgreSQL чи StorageService та не додаються окремими фотографіями в слайдшоу. У moderation snapshot зберігаються тільки стиль і кількість референсів; готова візуалізація з кімнатою, як і інші результати, доступна адміністраторам для модерації. Зміна стилю/фото скидає лише AI-preview, не ціну чи згоду на замовлення. Відповідь для старих параметрів не показується; під час підготовки фото запуск блокується.

Додаткові перевірки: `node scripts/test-table-ai-interior.mjs`, тести 10/11 фото, зміни/видалення, недопустимий формат і незмінність snapshot; тести сервісу перевіряють відповідний prompt, усі 10 передач і відсутність вихідних фото в архіві; Studio-тести перевіряють 11 multipart parts (стільниця + 10 кімнат), JPEG signature та ліміти. Тариф і ліміти підписки лишаються за чинним каталогом Студії; автоматичного додаткового списання за кожен референс не додано. Реальний платний запит і якість розміщення в кімнаті не перевірені.


## Уточнення результату (#491)

Marketplace передає optional `refinementImage` лише після перевірки власника фото в PostgreSQL/Storage. Студія перевіряє PNG, сигнатуру та межу 20000022 символів; файл стає останнім image[] після ескізу й максимум 10 кімнат (до 12 файлів). Це одна звичайна оплачувана генерація, без повторного використання попереднього резерву. Тариф і ключ визначаються чинними налаштуваннями адміністратора Студії. Суміжний UI генерує 1/2/4 зображення послідовними незалежними запитами, показує сумарну ціну та зберігає часткові результати.
