Мета задачі (task.md, Т1.6): за офіційною документацією перевірити контракти
Harness і Jev, закріпити версії; через наші адаптери пройти один повний цикл

## 2. Контракти (наші, провайдер — за адаптером)

- `CharacterSnapshot` (`server/core/flc/contracts.ts`, JSON Schema): герой, межа
  знань `as_of_chapter`, канон автора, підтверджені факти **лише з доказом**
  (абзац, глава, уривок), поточні стани, зв'язки, останні появи, ситуація,
  дозволені дії (`^[a-z_]{2,40}$`).
- `DecisionResult` (ТЗ-H §6.3): `selected_action`, `scores` (0–10),
  `raw_distributions`, `confidence`, `model_version`, `snapshot_hash`
  (sha-256 канонічного JSON знімка), `decision_trace_id`, плюс `source`
  (`jev` / `mock` / `llm_fallback`), `corrected`, `usage`, `latency_ms`.
- Питання допиту: Choice `next_action` (answer / lie / silence / deflect) і Score
  `fear_intensity` (5 рівнів → 0–10). Відповідь Jev: choice — `choice`,
  `probabilities`, `confidence`; score — зважена позиція 0…N-1, `legend`,
  `probabilities`, `confidence`.
- Серверний валідатор: обрана дія мусить бути з дозволеного списку; інакше —
  найімовірніша дозволена з розподілу, `corrected: true`.

## 3. Обмеження провайдерів

- **Jev:** 64k токенів на запит, з них 32k — стан плюс найдовше питання;
  1200 запитів/хв, 250k токенів/с («rate limits are adjusting dynamically»);
  лише текст; choice — до 255 варіантів, score — 2–10 рівнів; помилки 401, 422,
  429, 529 (повтор з відступом). Значення — модельні евристики, не діагноз і не
  доказ істини у світі книги.
- **Harness:** developer preview, «core plugins and APIs will continue to
  evolve»; сама DeepSeek не радить його для продакшн-бекендів.

## 4. Прогін циклу

Середовище сесії не має мережі до провайдерів (`api.typesafe.ai` і
`api.deepseek.com` відхилені проксі), тому прогін — з підставним Jev і
підставною LLM; справжні — через `TYPESAFE_API_KEY` / `DEEPSEEK_API_KEY` тим
самим скриптом (`npm run prototype:flc0`).

Тестова книга: 2 глави, 22 абзаци, героїня з тегами (страх, рішучість),
підтверджений факт із доказом, підтверджений зв'язок; межа знань — глава 1.

| Крок | Медіана, мс (7 прогонів, без мережі) |
|---|---|
| Retrieval (гібридний пошук, Т1.2) | 1 |
| Профіль (Т1.5) → знімок + перевірка схеми | 1 |
| Рішення (підставний Jev) + перевірка схеми | 0 |
| LLM (підставна) | 0 |
| **Весь цикл** | **3** |

Власні накладні витрати циклу — одиниці мілісекунд; час реального циклу
визначатимуть мережеві виклики Jev і LLM (їх виміряє той самий скрипт із
ключами).

**Розмір і вартість одного циклу (оцінка з заміру):** стан для Jev — 507
символів ≈ 170 токенів (+ ≈ 150 на два питання) → ≈ 350 вхідних токенів × $0.042
за млн ≈ **$0.000015**; знімок для LLM — 1442 символи → ≈ 630 вхідних і ≈ 50
вихідних токенів: `deepseek-flash` ($0.15 / $0.60 за млн) ≈ **$0.00013**,
Gemini 3.7 Flash ($0.75 / $3.75) ≈ $0.00066. На великій книзі знімок обмежено
схемою (≤ 60 фактів, ≤ 12 появ) — до ≈ 3k токенів стану, тобто < $0.0002 за
Jev на цикл.

Журнал агентів одного циклу — 16 подій (крок / виклик tool / результат / кінець
кроку), канон не змінено.

## 5. Що перевірено тестом (`test:flc-prototype`, 39/0)

Форма запиту до Jev (endpoint, Bearer, закріплена модель, choice-мапа,
score-масив, компактний стан); нормалізація відповіді й контракт; валідатор

журнал лише на дописування; повний цикл — знімок із доказами, **межа знань
глава 1** (ТЗ-H №5), **канон, рукопис і висновки не змінено** (ТЗ-H №3), збій
Jev → запасний шлях без втрати стану, вартість Jev за токенами; маршрут
`POST /api/projects/:id/flc/prototype` — лише адміністратор.

## 6. Рішення Н1–Н2: чи йде Harness у MVP

**Н1 — чи можна викликати Harness з бекенда:** технічно так. У репозиторії є
програмний API (імпорт TypeScript-пакетів), headless-режим CLI, сервер Agent
Client Protocol (ACP) і JSON-RPC. Модель DeepSeek задається `DEEPSEEK_API_KEY`
/ `DEEPSEEK_BASE_URL`.

**Н2 — чи можна вимкнути файли / оболонку / мережу:** так, але не одним
прапорцем ядра. Інструменти йдуть через конвеєр `tools/pre-execute`
(allow / ask / deny) і `tools/post-execute`. Заборони — плагінами:
`dsh-tool-policy` (deny-by-default правила), пісочниця `ctx.sandbox`
(`read-only` типово / `workspace-write` / `danger-full-access`). У headless-режимі
запит на підтвердження без сервісу підтвердження **сам відхиляється**
(fail-closed). Журнал подій `SessionEvent` пише той самий процес, тож це не
незалежний аудит.

**Рішення: у MVP Harness напряму не йде.** Причини: статус developer preview з
очікуваними несумісними змінами; сама DeepSeek не радить його для
продакшн-бекендів; заборона файлів / оболонки / мережі тримається на плагінах
і конфігурації, а не на гарантії ядра. Натомість — власний тонкий
`AgentRuntime` (`server/core/flc/runtime.ts`) з тим самим договором: агент
бачить лише зареєстровані серверні tools зі свого списку, scope сесії
незмінний, ліміти, таймаути й журнал. Адаптер Harness пишеться під цей самий
інтерфейс, коли Harness вийде з preview; до того — повернення до питання в
етапі 2 (Т2.x «AgentRuntime (наша реалізація + Harness за рішенням Т1.6)»).

**Jev — іде в MVP**, за адаптером і з запасним шляхом: REST стабільний, ціна
мізерна, форма відповіді збігається з потрібною ТЗ-H. Ключ — `TYPESAFE_API_KEY`
(або платформний ключ рушія `typesafe`), модель — `TYPESAFE_JEV_MODEL`
(типово `jev-1.13.0`).
