# Краудфандинг STEAM у Студії

Адмінпанель → «Краудфандинг STEAM» відкриває спільні кампанії маркетплейсу. Фінансовий сервер і PostgreSQL містяться в Fusion-Lab-Marketplaes; локальних копій внесків/траншів у Студії немає.

Модель: 100% цілі до першого авансу; 3% платформі, 97% команді; етапи за незмінним snapshot паспорта. Банківські перекази виконує оператор у банку, а панель приймає документи фактичних операцій. Кнопка схвалення резервує кошти та не виконує переказ.

Сервер `server/fundingBridge.ts` пропускає тільки фінансові admin-маршрути, застосовує requireAdmin і передає Firebase UID із сесії. Спільний API повторно знаходить користувача, перевіряє funding:read/review/payout та записує його канонічний actorId. UID/actorId із JSON не можуть замінити серверну особу. Дизайнер меблів не має доступу до цього вузла.

`FundingPanel.tsx` використовує штатний транспорт `/api/` з автоматичним `/studio` префіксом. Bridge secret ніколи не передається браузеру. UI оформлений у темній палітрі adminOS. Візуальні компоненти й типи у `crowdfunding/` є синхронізованим знімком `apps/web/src/components/crowdfunding/funding-admin.tsx`, funding-types.ts і funding.css маркетплейсу; при змінах обох інтерфейсів оновлювати їх разом і звіряти хеші.

До розгортання Студії розгорнути marketplace API з міграцією `20261027000100_steam_crowdfunding` та окремим FUNDING_BANK_KEY. Після міграції внески початково вимкнено. Оператор має заповнити свої фактичні умови/отримувачів і переконатися, що банківський сервіс підтримує таку модель зборів. Тестових production кампаній і реальних оплат під час QA не створювали.

Повний регламент: `docs/steam-crowdfunding-operations.md` у репозиторії маркетплейсу. Перевірка allowlist: `node --import tsx scripts/test-funding-bridge.mts`. Браузерний інтеграційний прогін у marketplace рендерить ті самі React-компоненти з реальною Nest/Prisma базою fixtures; після деплою потрібна окрема перевірка HTTP-мосту й відкриття цього вузла під адміністратором.
