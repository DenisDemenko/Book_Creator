# Т9.9 — оформлення Studio та публічного читача

13.10.2026, журнал #434. Оформлення реалізовано й перевірено локально.
Підстава: попередні скриншоти показували ізольований компонент, а
публічний HTML мав окремий спрощений шаблон. Тепер візуальний прогін
завантажує справжні `main.tsx`/`App.tsx`, HeaderNav, SidebarNav та
StudioBackdrop через Vite з базовим шляхом `/studio/`.

## Зміни

- Панелі автора, inbox і погодження: типографіка Studio, скляні картки,
  акцент «Сонечка», статуси учасників, лічильник погоджень, поля,
  кнопки та окремий перегляд рукопису як книжкової сторінки.
- На 390px кнопка оновлення переноситься на власний рядок. Заголовки
  погодження мають ширину 156–164px і не складаються в колонку літер.
- Публічний читач: справжні логотип і фон Fusion Lab Studio, світла/темна
  тема, книжкова сторінка, навігація, карта з маркером і титульний склад.
- Тема читача зберігається в `nova_theme`. Друк прибирає керування та
  карту, показує повний лінійний текст, авторів і ліцензію.
- HTML самодостатній: брендовані зображення вбудовані з публічних
  build-assets. CSP, екранування тексту, серверні права, snapshot і
  умови експорту збережені.
- Налаштування власника щодо прозорості блоків Studio збережене.
  Оформлення інших модулів не змінювалося.

## Перевірки

| Перевірка | Результат |
|---|---|
| `npm test` | exit 0; модель видань 10/0 включена до повного набору |
| `npm run lint` | exit 0 |
| `npm run build` з `/studio/` | exit 0; попередження про великий bundle залишається |
| `test:labyrinth-edition:browser` | 12 браузерних перевірок і 33 API-перевірки |
| `test:labyrinth-edition:studio` | 12 повних екранів, 33 API-перевірки, 0 JS errors |
| Журнал і посилання | 434 записи, journal tests 76/0; 17 локальних посилань нових MD існують |

Повний `npm test` виконано після основних змін оформлення. Після фінального
переносу мобільної кнопки повторено цільові браузерні перевірки, повну App,
типи та build; після документації — журнал і `git diff --check`.
Для повторення visual harness у цій хмарній Linux-середі потрібні
ізольована тестова PostgreSQL-база в `CORE_TEST_DATABASE_URL` та Chromium
`/usr/bin/chromium`. Команда: `npm run test:labyrinth-edition:studio`.
Вона не входить до звичайного `npm test` й не використовує production-вхід.

Перші спроби нового visual harness виявили неналаштоване Vite HMR та
гонку очікування форми. Виправлено прив'язку HMR до тестового HTTP-сервера
й очікування фактично завантаженого тексту/checkbox. Невдалі спроби не
зараховані як PASS. Після виправлень повний прогін завершився з exit 0.

## Межі й залишок

Це локальна перевірка інтерфейсу та справжніх API видань/читача на
ізольованих PostgreSQL/SQLite. Identity й сторонні API — тестові fixtures.
Реальний Firebase-вхід та робота всіх інших модулів не перевірялися.
Зовнішні браузерні запити блокувалися, тому заявлені шрифти використовують
локальні системні fallback; фактичне завантаження web-fonts ще слід звірити
після деплою. Автоматичної оцінки всіх WCAG-критеріїв не виконували.

Production-приймання Т9.9 залишається **0/16**; Safari/Android, екранний
читач, реальні ролі/grants/підписки, файли у сторонніх читачах і друкарня
потребують [окремого живого прогону](../acceptance/T9.9.md). Railway rollout
Т9.9 у цій роботі не перевірявся. Стан коміту й пуша дизайну описано
в [журналі #435](../../log/301-350.md).

Т9.10 не розпочато. [Детальне завдання обох пунктів](../labyrinth/T9.9-T9.10-DETAILED.md)
визначає два різні проходження, дві окремі книги, незалежні погодження,
публікації та докази результату.
