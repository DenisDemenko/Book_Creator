## Розворот за обраним рушієм — уточнений контракт

У [registry.ts](../../server/pdf/engines/registry.ts) зареєстровано **чотири** рушії: Nova, DesignCraft, Chromium, Pandoc. Gamma є в типах, але навмисно не зареєстрована. Доступність кожного залежить від середовища; продакшн-доступність усіх чотирьох цим аудитом не перевірялась.

Зараз `pdfEngineId` — локальний useState панелі DesignSuggestionPanel. Зміна селектора не передається до BookPreviewView; App передає йому лише book і totalWords. Сам розворот використовує useRealBookPages та HTML, не викликаючи вибраний PDF engine.

Залишилося:

1. Зберігати вибір рушія у спільному стані книги/налаштувань перегляду, щоб переходи між розділами його не губили.
2. Будувати розворот із фактичного результату обраного рушія: його шрифтів, теми, семантичних блоків, зображень, переносів і сторінок.
3. Використовувати той самий snapshot книги, layout і тему для розвороту та експорту; кешувати з урахуванням рушія й актуальності джерела.
4. Передати реальну кількість сторінок і, де реалізовано, pageMap у зміст та навігацію.
5. Перевірити сценарій звичайного автора-власника. Наявний багаторушійний `/api/admin/pdf/preview` обмежений requireAdmin; окремий авторський theme-preview зараз стосується DesignCraft.
6. Перевіряти кожен доступний рушій окремо. Фіксований HTML-preview чи DesignCraft для всіх виборів не виконує цю вимогу.

Теми Book Design Studio мають власні можливості DesignCraft; при виборі іншого рушія розворот повинен відповідати можливостям і реальному результату саме цього рушія.

## Відтворені проблеми

Контрольні приклади виконували реальні функції з поточного source, з ізольованими даними. Це не браузерне або production-приймання. Машинні результати: [evidence.json](WRITER_PLATFORM_PLAN_AUDIT_2026-10-15.evidence.json).

1. **Невдале збереження не блокує синопсис.** Реальні persistCast → flushCastSave → goTo(4), API контрольовано відхилено. Послідовність: `step:4 → PATCH_failed → suggest:synopsis`. Причина: catch у persistCast поглинає помилку; goTo змінює step до запису. [Код](../../src/components/ExpressWizardView.tsx).
2. **ID зберігаються не наскрізно.** Після видалення першого героя зі списку без клієнтських ID наступний отримав `hero-a` замість `hero-b`: normalizer спершу зіставляє за індексом. Цей вхід можливий після suggest: клієнт бере cast із ненормалізованого payload. Додатково справжній App.applyExpressPlan створив новий char-express ID замість переданого ID. [Сховище](../../server/expressStore.ts), [App](../../src/App.tsx).
3. **HTML фото не нормалізовано.** renderSectionBlocksHtml повернув `<p><figure>…`, `src="/api/media/…"` і `shape-outside:url(/api/media/…)`. figure усередині p — невалідна структура. Префіксування властивості img.src не виправляє рядок, який потрапляє через innerHTML. [Код](../../src/utils/helpers.ts).
4. **Розташування semantic metadata відрізняється від опису PR.** Теги є, але справжній ланцюжок передавання дає `[AI-DRAFT] → semantic tags → текст → [/AI-DRAFT]`. Обіцянка PR «перед AI-DRAFT» цим не виконується. Helper-тест із уже загорнутим AI-DRAFT не перевіряє цю послідовність. Треба узгодити контракт розташування та перевірити доступність тегів ядру на реальному імпорті.
5. **Частковий префікс не доповнюється.** Якщо summary починається лише з `[/chapter:…]`, handoff залишає його без outline і character. Перевірка alreadyTagged припиняє додавання всього префікса. [Код](../../src/utils/expressSemanticHandoff.ts).
6. **Корінець має різні значення.** Для 200 сторінок paperback UI порахував 10.4 мм; calculateFullCover — 11.43 мм для білого паперу і 12.7 мм для кремового. У CoverConfig ще немає узгодженого вибору паперу, який визначав би один результат. [UI](../../src/components/CoverDesignerView.tsx), [KDP](../../server/kdpSpec.ts).

Окремо підтверджено читанням коду:

- ExpressDraft / PATCH не мають revision і CAS; updateDraft оновлює за id без перевірки очікуваної версії.
- Кнопки Назад і зміна напряму обходять flushCastSave; cleanup скасовує debounce.
- suggest('cast') записує новий склад на сервері й замінює клієнтський cast без окремого вибору Додати/Замінити/Ігнорувати.
- Перед генерацією synopsis немає readonly-підтвердження конкретного складу/конфлікту/задуму.
- Hook пагінації міряє DOM одразу після innerHTML; немає очікування img.decode/load та перерахунку після завантаження.
- Зміст і видимі номери в розвороті ще викликають helpers, що використовують стару 850-symbol евристику.
- PdfRenderResult має pageCount, але не має pageMap.

## Що в початковому описі вже застаріло

- «Немає flush перед Далі» — частково застаріло: flushCastSave уже є для першого переходу до Е4/Е5. Залишаються поглинання помилок, ранній setStep, переходи назад/закриття та конфлікти.
- «Немає ID cast» — застаріло для серверного normalizer, але наскрізної ідентичності до книги ще немає.
- «Semantic handoff — лише helper; Gate B ще не запустився» — застаріло: реальна точка виклику підключена, PR злитий, Gate B зелений.
- «Zoom реалізований через transform: scale» — для поточного BookPreviewView не відповідає коду: він уже використовує CSS zoom. Необхідні 10–150%, Fit та інші вимоги ще відсутні.
- «Потрібно створити PDF/semantic/theme основу з нуля» — не потрібно: відповідні адаптери й DesignCraft pipeline уже є, їх треба узгодити зі спільним preview та вибором рушія.
