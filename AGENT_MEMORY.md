## 3. Архітектура, важлива для поточних задач

### 3.1. Пагінація і розворот **[Факт — код]**

- `BookPreviewView.tsx` застосовує `useBookPreviewMeasurement` із `src/utils/useRealBookPages.ts`: сторінки уточнюються вимірюванням HTML у браузері після початкової оцінки `buildBookPages`. Вимірювання чутливе до асинхронного завантаження медіа.
- «Зміст» та частина сценаріїв «Верстки PDF» іще спираються на евристичний підрахунок `buildBookPages`; **номери можуть відрізнятися** від DOM-пагінації та PDF.
- `server/pdf/engines/designcraftEngineV3.ts` — окремий серверний рушій; його результат включає `pageCount` і `toc.entries`, але з перевіреного коду **не встановлено придатного для Studio контракту `chapter → pageMap`**.
- У «Розвороті книги» масштаб `zoom` зараз обмежений **50–200 %**, а повзунок унизу має лише крайні числа (`1` / `totalBookPages`), **без міток початку глав**. Це не перемикач масштабу шаблонів (пункт 1 плану).

### 3.2. DesignCraft і дизайнер шаблонів

- У Studio рушій викликається через `DESIGNCRAFT_PATH`, типовий виклик `designcraft-cli`, файл `server/pdf/engines/designcraftEngineV3.ts`. **[Факт — код]**
- Походження CLI саме від `github.com/storytold/designcraft` і сумісність версій **[Не перевірено]**: не приймати збіг назви за доказ.
- У `src/components/DesignerThemeStudio.tsx` **досі** `type ZoomMode = 75 | 100 | 'fit'`, а вибір — `75 %`, `100 %`, `Fit`. Вимога **10–150 % з кроком 10 %** **НЕ реалізована в цьому файлі** станом на перевірку. **[Факт — код]**
- Принцип інтеграції: розвивати чинні розділи/екрани, не видаляти наявне; автор пише в «Книга & Текст», а дизайн керує представленням і версткою. React-UI поверх канону та CLI для PDF — **пропозиція**, не остаточно затверджене технічне рішення.
- До змін пагінації перевірити можливості CLI щодо `pageMap`, друкованого формату, обкладинки та синхронізації розвороту із серверним PDF.

### 3.3. Майстер «Книга за 5 хвилин» (Express)

- Серверні `server/expressRoutes.ts` / `server/expressStore.ts`, SQLite `express_drafts`, чернетка за ID в `localStorage` (історично ключ `nova_express_draft_id`). **[Факт — код / журнал]**.
- На момент перевірки `server/expressStore.ts` **вже містить** ревізію та CAS-перевірку `expectedRevision`, а `server/expressRoutes.ts` окремо обробляє пропозицію `cast` за наявного складу (`needsConfirmation`). **Не повторювати стару тезу, ніби цих захистів у коді немає.**
- Симптом зникнення/підміни героїв та асинхронний `flush` на переході між кроками — **[Не перевірено в живому сценарії]**. Спочатку відтворити два швидкі додавання → «Далі» → повторне відкриття → генерацію синопсису, а потім локалізувати залишкову причину.
- Перед введенням нового API контракта звірити наявний `revision`, щоб не вводити другий паралельний механізм версій.

### 3.4. JEV і рішення героя

- Наявні модулі JEV/LLM fallback: `server/ai/adapters/jev/` та `server/core/jevLevels.ts`; у коді є fallback та облік джерела оцінки **[Факт — код]**.
- Модель `jev-1.13.0` і адреса `https://api.typesafe.ai/v1/systemone` наведені в попередньому технічному аналізі **[Факт — історичне джерело; актуальну конфігурацію production не перевірено]**.
- Пропозиція для Express: JEV-оцінювання інтенсивності кроків кривої героя + можливість авторського override. Наявність завершеного окремого маршруту `POST /api/express/arc/evaluate`, що виконує саме цей контракт, **[Не підтверджено]**; не позначати задачу 5а виконаною.

### 3.5. Обкладинка і зображення

- `CoverConfig` у `src/types.ts` зберігає, зокрема, `frontArtUrl`, `backDescription`, `coverImageUrl`, але **не містить окремих явних полів** для зображення задньої сторони, вибору типу паперу та повної друкованої розгортки. **[Факт — код]**
- `server/kdpSpec.ts` має `PaperType`, `PAGE_THICKNESS_INCHES`, `calculateFullCover` і окремий друкарський контракт. Звести логіку обкладинки до спільного розрахунку; не вигадувати нові незалежні формули корінця.
- `src/utils/basePath.ts` нормалізує `fetch` / атрибути media DOM, а `BookPreviewView.tsx` виводить HTML через `dangerouslySetInnerHTML`. **[Гіпотеза]** непереписані адреси на кшталт `/api/media/file/...` у готовому HTML обходять патч `setAttribute` і не потрапляють під rewrite `/studio`. Це правдоподібна причина «іконки замість фото», але потрібна репродукція з Network/404 на preview під `/studio`.

- Початковий план згадує **каталог ручних сценаріїв на 617 кроків**, їхню класифікацію `PASS / PASS+NOTE / FAIL / BLOCKED / N/A` та базовий коміт `8cd586f5f73dc533fb612e8dbab74c7064dbba54` — **[Факт — наданий документ; не звірено з поточним каталогом]**.
- **Ні GitHub-наявність скрипта, ні статус TypeScript/CI, ні зелена збірка не замінюють ручного acceptance на тому самому SHA.** Якщо тест не запускався, прямо писати «не запускався».

## 6. Ризики та запобіжники

- Пагінація у клієнті й CLI відрізняється: просте перемикання джерела зробить рендер асинхронним і може зламати посилання змісту.
- Переписування media URL у HTML може вплинути на експорт / PDF та безпеку HTML; кожен канал перевіряти окремо.
- JEV — зовнішній сервіс із затримками, ціною, лімітами; кеш і fallback обов'язкові.
- Express revision уже існує; не вводити несумісну другу модель без міграцій.
- Ігрові сесії можуть містити чутливу інформацію: **тег також може деанонімізувати людину**. Спершу авторитетні дозволи/згоди, потім тегування, не навпаки.
- Story & Experience семантичний імпорт поки зберігає текстові теги й локальний provenance, **не** гарантує атомарного збереження зв'язків PostgreSQL; не називати завершеним «118 сутностей + 39 зв'язків».
- Кілька активних агентів/гілок можуть оновити `master` чи робочу гілку: перед правкою дивитися `git status`/актуальний SHA; при конфлікті не перезаписувати чужу працю.
