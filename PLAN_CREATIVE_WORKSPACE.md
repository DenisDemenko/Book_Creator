# Т7.4 — приватний Creative Workspace

Studio — власник приватного проєкту, файлів, версій і review. Marketplace дає
перехід тільки власнику/обраному фахівцю. Автор або обраний активний учасник
із явним чинним доступом до конкретного Workspace відкривають його; VIEW тільки
читає, WORK додає власні роботи й коментарі. Вибір фахівця не є grant.
Скасований/архівний/завершений проєкт зберігає історію без нових записів.
Owner-only підтверджена видача/відкликання у вкладці «Учасники»: область
deliverable/<creativeProjectId>, WORK → edit тільки цієї області. Чинний
media_library VIEW/WORK підтримується, але не потрібний для власних робіт.
Workspace-only grant не додає права на медіатеку/рукопис; Core book access
не розширюється. Дати й активна участь перевіряються на кожному запиті.

SQLite: файли BLOB і метадані ревізій, annotations, append-only events,
курсор прочитаного. Межа 20 МБ, дозволені формати з перевіркою сигнатури;
файловий endpoint перевіряє права кожного разу, без зовнішніх публічних URL.
Quota обліковується на завантажувача наявним механізмом Studio.
Нова версія починається DRAFT і не змінює байти/статус старої; конкурентне
додавання перевіряє parent revision і latest. Статуси й вирішення annotation
CAS, рішення автора вимагає явного підтвердження. APPROVED/FINAL не CANON.

Вкладки §6.1, desktop три колонки, mobile вкладки; перегляд image/video/PDF,
zoom/fullscreen, порівняння зображень поруч/до-після/overlay. Pins нормовані
x/y, video timecode. Чат: текст, згадування, приватні вкладення, системні
події, історія з курсором, непрочитані; оновлення polling 5 с з повторною
перевіркою доступу. Структура рукопису лише через scoped GET_AVAILABLE_CONTEXT.
AI Tools веде до наявної AI Studio; ключі не віддаються, генерація/канон
не викликаються автоматично. Style Bible — наступний Т7.6.

Перевірки: Memory/PostgreSQL для grants/учасників; справжній SQLite для
контенту; auth/expiry/revoke/frozen status; незмінні файли й CAS; review/annotation
і chat/read; браузерний цикл та 390px; повні npm test, lint/build, журнал.
Production Firebase і реальні акаунти — окремий ручний сценарій.
