# Creative Studio — Т7.1

Розподіл за рішенням #304: профілі та заявки — Marketplace, приватні
CreativeProject та доступ до книги — Studio.

- Розширити SellerProfile даними фахівця, не дублюючи ідентичність. Окремий
  цикл модерації DRAFT → SUBMITTED → UNDER_REVIEW → APPROVED / NEEDS_CHANGES /
  REJECTED; версія для захисту від одночасних рішень. Старі заявки продавця
  лишаються заявками продавця. Схвалення фахівця не надає продажів.
- Публічно показувати лише схвалені профілі; чернетки та зауваження приватні.
- Зберігати CreativeProject у SQLite поруч з книгою, тільки власником.
  На цьому етапі specialistId/orderId порожні; жодних автоматичних grants.
- Довідник п’яти станів функцій. Робочі посилання лише для AVAILABLE/BETA;
  заплановані workspace, briefs, payments без удаваних кнопок запуску.
- Перевірити переходи, доступ, CAS, міграцію, сумісність seller pipeline,
  persistence, UI, типи та збірки. Реальний Firebase/прод — окрема прийомка.

Т7.2 і далі: бриф, вибір фахівця, grants і робочий простір не входять у Т7.1.
