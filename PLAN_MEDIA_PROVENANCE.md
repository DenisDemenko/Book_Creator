# Т7.5 — медіатека з походженням

## Результат

Власник явно переносить конкретну APPROVED/FINAL версію з Creative Workspace
до своєї приватної Media Library. Зберігаються байти, MIME, книга, творчий
проєкт, початковий автор/дата, вихідні root/parent/version/revision, декларація
ШІ, хто й коли затвердив саме цю версію, хто її переніс. Фахівець не отримує
нових дозволів. Рукопис, учасники, grants, Visual Bible й канон не змінюються.

У наявній медіатеці додано вкладку «Походження»: усі файли й версії,
зокрема зображення, відео, аудіо, PDF, ZIP і GLB. Галерея лишає останню
версію кожної групи; старі версії доступні в паспорті й новій вкладці.
Дія перенесення — у «Роботах» Workspace після затвердження.

## Дані й доступ

Типи: IMAGE, VIDEO, COVER, REFERENCE, DOCUMENT, AUDIO, SOURCE_FILE, OTHER.
Статуси: DRAFT, REVIEW, APPROVED, REJECTED, ARCHIVED; CANON відображається
в переліку; його встановлює лише окрема підтверджена дія Visual Bible (Т7.6),
не звичайний редактор метаданих. Див. PLAN_CREATIVE_BIBLE.md.
Старий паспорт draft/final і ліцензії збережено. Legacy final означає готовий
файл, а не зафіксоване людське затвердження: новий статус DRAFT, approval=null.
Для старих записів автор/використання ШІ, яких не зафіксовано, не вигадуються.

`media_assets.provenance` — JSON-колонка SQLite з additive migration.
JSON fallback зберігає ті самі поля; помилки запису передаються клієнту,
а наступна спроба не блокується попередньою помилкою. Media Library зберігає
байти у DATA_DIR/media, Workspace — у SQLite BLOB. Перенесення створює
додаткову копію; потрібні SQLite і persistent volume, який містить обидва.

`creative_workspace_imports` — durable correspondence та tombstone після
видалення файла медіатеки. Детермінований media ID, PK і серіалізація одного
ланцюжка запобігають дублюванню. Metadata/history/import map/Workspace event
записуються однією синхронною SQLite-транзакцією після запису файла.
Повторне перенесення повертає наявний файл; після видалення — 410.
Порядок імпорту не змінює вихідні номери версій. Попередні байти не стираються.
Нова версія імпортованої роботи додається через Workspace, зі своїм review;
звичайний image upload не може вставити її в цей ланцюжок повз затвердження.

Авторство, вихідна версія, імпорт і Workspace approval не редагуються клієнтом.
Підтверджені правки типу/статусу/тегів/сутностей використовують metadata revision
CAS і пишуться в історію. Нові незалежні файли затверджує власник явно;
зміна metadata status не змінює рішення review у Workspace.

Походження від персонажів/локацій — Core entity IDs цієї книги з перевіркою
типу, сцени — IDs сцен рукопису. Owner-only `/provenance-targets` повертає саме
цей простір ID. Це дані «на основі чого створено»; поточні прив’язки ілюстрацій
редагуються через наявний MediaLinksPanel/API Т2.3 (там сцени — Core document IDs).
Назви/байти/секрети прихованих сцен до provenance не копіюються.

## ШІ

Форма завантаження Workspace фіксує для кожної версії used=true/false/null,
provider/model, generation ID, prompt reference та дозволені прості settings.
Параметри не успадковуються мовчки від попереднього файла. Для used=true
обов’язкові provider/model; ідентифікатори не приймають текст промптів чи
підписані URL. Вкладені дані, ключі/токени та невідомі параметри відхиляються.
FORBIDDEN потребує used=false, DISCLOSE — явного true/false; опублікований
бриф має пріоритет над чернеткою. Заява про зовнішню генерацію — декларація
завантажувача, не незалежна перевірка чужого провайдера.

Наявний серверний image/video pipeline передає фактичний провайдер і модель,
відомі налаштування. Відсутні provider generation ID не вигадуються. Дані
серверної генерації та вихідна декларація Workspace не переписуються через
редактор медіатеки. Legacy prompt/model лишаються в старому приватному паспорті;
новий блок походження не копіює повний текст промпта або ключі зі сховища.

## Межі й перевірки

Фільтри: тип/статус/автор/дата/творчий проєкт/ШІ-ручна-невідомо/теги/
персонаж/локація/сцена. API `/api/media/list` підтримує ті самі фільтри.
Файл перевіряє доступ на кожному запиті, private/no-store/nosniff;
документи й вихідні файли завантажуються як attachment. Workspace приймає
MP3/WAV/OGG додатково до форматів Т7.4, із перевіркою сигнатур, до 20 МБ.
Існуючий image upload і чат підтримки не розширено до довільних вкладень.

Quota перенесення перевіряється на власника додаткової копії; успішний
ідемпотентний повтор не списує байти знову. Чинний механізм квот резервує місце
до запису: відхилена після резервування спроба не отримує автоматичного refund.
Недостатня квота, змінена ревізія, заморожений проєкт або втрачена власність
не створюють імпортованого матеріалу. Перенесення не підтверджує ліцензій:
для замовлення типово unknown, ліцензію власник заповнює окремо.

Автоматично: реальні Express/SQLite/JSON, Memory і PostgreSQL Core,
конкурентність, privacy/CAS/AI policy/історія, браузерні компоненти й 390px.
Реальні Firebase-логіни, production volume/redeploy та платні AI-виклики —
окреме приймання [T7.5](docs/acceptance/T7.5.md). Marketplace цього етапу не
потребує нової міграції чи зміни коду. Visual/Style Bible реалізовано окремим Т7.6: PLAN_CREATIVE_BIBLE.md.
